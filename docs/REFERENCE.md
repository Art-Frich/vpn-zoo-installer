## Что вы получите

|---|---|---|---|---|---|
| `vless-reality` | VLESS + REALITY + Vision | TCP 443 | вкл. | Основной TCP: выглядит как TLS к чужому сайту | v2rayN ≥7.25, v2rayNG ≥2.2.6, Happ, INCY, Streisand, Throne; mihomo ≥1.19.31 (подписка/YAML) |
| `vless-xhttp` | VLESS + XHTTP + REALITY | TCP, случайный порт | вкл. | Запасной TCP: свой порт, свои ключи и SNI, не падает вместе с 443 | v2rayN, v2rayNG, Happ, Throne; mihomo ≥1.19.22 |
| `ss2022` | Shadowsocks-2022 | TCP+UDP, случайный порт | `ENABLE_SS=1` | Запасной без TLS. Выключен по умолчанию: в полевом тесте соединения с реальных клиентов теряли данные (research/2026-10-05) | v2rayN/v2rayNG, Happ, Hiddify, sing-box, mihomo |
| `hysteria2` | Hysteria2 | UDP 443 | вкл. | Основной UDP (QUIC), быстрый на плохих каналах; ссылка первой версии продолжает работать | hysteria 2.12, v2rayN/v2rayNG, Happ, mihomo, Throne |
| `amneziawg` | AmneziaWG 2.0 | UDP, случайный порт | вкл. | Полный L3-туннель, обфусцированный WireGuard; в клиентах нет локального прокси | AmneziaVPN ≥5.0.1.5, AmneziaWG ≥2.0, WG Tunnel ≥4.2, DefaultVPN (iOS), mihomo ≥1.19.14 |
| `hysteria2-obfs` | Hysteria2 + Salamander | UDP, случайный порт | вкл. | QUIC, который не похож на QUIC: если режут по сигнатуре QUIC | hysteria, sing-box, mihomo, v2rayN/v2rayNG |
| `tuic` | TUIC v5 | UDP, случайный порт | вкл. | Ещё один QUIC-протокол для клиентов на sing-box | sing-box/SFA/SFI, Hiddify, Karing, NekoBox, mihomo |
| — | Cloudflare WARP | исходящий | `ENABLE_WARP=1` | Выход для echo-сервисов «мой IP» (и RU по флагу) не с адреса сервера | — |

Движки: VLESS, XHTTP, SS-2022 и TUIC — Xray внутри [3x-ui](https://github.com/MHSanaei/3x-ui) v3.9.0 (Xray 26.9.30); Hysteria2 — standalone [HyNetworks/hysteria](https://github.com/HyNetworks/hysteria) v2.12.3; AmneziaWG — модуль ядра (DKMS) или `amneziawg-go`. Всё скачиваемое закреплено в [scripts/versions.env](../scripts/versions.env) и проверяется по sha256.

**Важно про клиентов VLESS/XHTTP.** Xray 26.9.30 на сервере отклоняет ClientHello без X25519MLKEM768. Клиенты на sing-box (SFA/SFI, Hiddify, NekoBox, Karing), Shadowrocket и старые ядра Xray показывают «подключено», но трафика нет. Для VLESS и XHTTP берите клиент на ядре Xray ≥26.x. Hiddify на стенде (07.10.2026): VLESS и AmneziaWG не работают, TUIC и Shadowsocks работают, Hysteria2 и Salamander — без проверки сертификата (оговорка в админке); через него идёт всё устройство, поэтому в готовые варианты он не входит.

Кроме протоколов:
- анти-утечки: echo-сервисы «узнай свой IP» через туннель блокируются или идут через WARP, sniffing, журналы посещений Xray выключены, BitTorrent заблокирован, из туннеля не видны сервисы самого сервера;
- панель 3x-ui слушает только `127.0.0.1`, доступ через `ssh -L`;
- режим «только выбранные приложения»: через VPN идут только зарубежные приложения из каталога (Brave, Telegram, YouTube, WhatsApp, Instagram, X, Discord, Signal, ChatGPT, Claude), остальное мимо; по умолчанию в QR зашит весь каталог — лишнее пользователь отключает сам; список приезжает в QR AmneziaWG для Android и в правилах v2rayN для Windows ([Приложения через VPN](#приложения-через-vpn));
- инструмент `zoo`: пользователи во всех протоколах сразу, ссылки и QR, трафик, самопроверка, обновление версий, веб-админка;
- UFW (default deny), fail2ban, unattended-upgrades;
- по флагу `SSH_HARDEN=1` — SSH на случайном порту и только по ключу, без риска потерять доступ ([Закрыть SSH](#закрыть-ssh)).

## Установка

Нужно: VPS с Ubuntu 22.04 или 24.04 (x86-64; arm64 не проверен), root или пользователь с `sudo`, systemd, около 1 ГБ свободного места. Не ставьте поверх чужого 3x-ui, Hysteria или AmneziaWG без `--force`: инсталлер найдёт их и остановится.

```bash
sudo apt-get update && sudo apt-get install -y git     # если git нет (минимальные образы хостеров)
sudo git clone https://github.com/Art-Frich/vpn-zoo-installer.git /opt/vpn-zoo-src
cd /opt/vpn-zoo-src
sudo bash scripts/install.sh
```

На реальном VPS установка шла около 30 минут, большую часть — скачивание с медленного в тот день GitHub; оборванная загрузка докачивается при повторном запуске. Каталог клона не удаляйте: из него `zoo upgrade` берёт новые версии. Все команды `sudo bash scripts/install.sh …` ниже запускаются из него (`cd /opt/vpn-zoo-src`).

**Перезагрузка.** На Ubuntu 22.04 со старым ядром фаза 02 может поставить HWE-ядро 6.8 (для модуля AmneziaWG) и попросить перезагрузку. Тогда `sudo reboot` и та же команда ещё раз: установка продолжится с места остановки. Если хостер не даёт сменить ядро, запустите с `AWG_NO_HWE=1`: AmneziaWG пойдёт в userspace (`amneziawg-go`).

**Где ключи.** Фаза 99 печатает ссылки и QR пользователя `owner` по каждому протоколу, `.conf` и ключ `vpn://` AmneziaWG, команду туннеля к панели и таблицу «какие клиенты с чем работают». То же сохраняется в `/root/CREDENTIALS.md` (0600). Позже ссылки выдаёт `sudo zoo links owner --qr`.

Файлы на сервере:

| Путь | Что |
|---|---|
| `/etc/vpn-setup/config.env` | параметры и секреты (0600) |
| `/etc/vpn-setup/protocols.d/*.json` | манифесты протоколов |
| `/etc/vpn-setup/users.json` | реестр пользователей |
| `/etc/vpn-setup/groups.json` | группы пользователей (протоколы, клиенты, список приложений) |
| `/etc/vpn-setup/clients/<имя>/` | ссылки и конфиги пользователя |
| `/etc/vpn-setup/probe-export.json` | пакет для клиентского пробника (ключи `zoo-probe`) |
| `/etc/vpn-setup/allowlist.json` | какие приложения идут через VPN ([ниже](#приложения-через-vpn)) |
| `/etc/vpn-setup/journal-ignore.txt` | «свои» сети журнала атак ([ниже](#журнал-атак-кто-нас-щупал)) |
| `/root/CREDENTIALS.md` | ключи `owner` и команда туннеля к панели (0600) |
| `/opt/vpn-zoo/` | установленная копия `zoo` (обновляет фаза 09) |
| `/var/lib/vpn-setup/state` | какие фазы пройдены |
| `/var/lib/vpn-zoo/` | данные zoo: `traffic.sqlite`, `journal.sqlite`, `probe-history.sqlite`, итог самопроверки `probe-local.json`, `dist/` (дистрибутивы), `upstream.json` и `clients-versions.json` (кэш версий), сессии админки |
| `/var/log/vpn-zoo/install-*.log` | журналы установки (с ключами; хранятся 10 последних) |
| `/var/backups/vpn-setup/<время>/` | бэкапы перед перезаписью конфигов |

## Самопроверка в конце установки

После итога `install.sh` поднимает на самом сервере клиент каждого протокола (`zoo probe --local`), подключается к публичному IP сервера и делает малый запрос, загрузку 5 МБ и проверку IP выхода. Получается таблица «работает в принципе»:

```
протокол        порт       работает в принципе  итог  скорость
amneziawg       27559/udp  да                   OK    110 Мбит/с
hysteria2       443/udp    да                   OK    180 Мбит/с
vless-reality   443/tcp    да                   OK    59 Мбит/с
...
Работает в принципе: 6 из 6.
```

Протокол, который не работает даже на самом сервере, выделяется красным «НЕ РАБОТАЕТ на самом сервере» с причиной и командой для подробностей. Установку это не прерывает. Ниже таблицы — готовые команды для следующего шага (проверки с вашей машины).

- Проверка идёт кредами служебного пользователя `zoo-probe`, не `owner`: проба не выбивает сессию AmneziaWG у телефона владельца и не смешивается с его трафиком.
- Если хостер не пускает трафик с сервера на его же публичный IP (нет hairpin), проба повторяется через `127.0.0.1`, в отчёте будет `куда: loopback`.
- Итог сохраняется в `/var/lib/vpn-zoo/probe-local.json` (страница «Проверка» админки) и вкладывается в пакет `/etc/vpn-setup/probe-export.json`.
- Повторить самопроверку и пересобрать пакет: `sudo zoo probe --local --summary --export /etc/vpn-setup/probe-export.json`. Отключить при установке: `ZOO_SELFTEST=0`.

## Блокирует ли ваш провайдер: пробник на вашей машине

«Работает в принципе» ещё не значит «работает у вас». Второй шаг — тот же набор проверок из вашей сети: контейнер `zoo-probe` подключается к серверу через вашего провайдера и сравнивает результат с самопроверкой сервера.

Нужны Docker (на Windows и macOS — Docker Desktop), `git` и `ssh`/`scp` (в Windows 10/11 OpenSSH встроен). **Пробник должен ходить к серверу через вашего провайдера, а не через ваш VPN.** Выключите VPN на время проверки или, если выключать нельзя, исключите из него только адрес сервера: Windows (PowerShell от администратора) — шлюз из `Get-NetRoute 0.0.0.0/0`, затем `route add СЕРВЕР mask 255.255.255.255 ШЛЮЗ`; macOS — `sudo route -n add -host СЕРВЕР ШЛЮЗ`; Linux — `sudo ip route add СЕРВЕР via ШЛЮЗ` (проверено с Hiddify в режиме TUN). Если трафик всё ещё перехватывает VPN, пробник предупредит об этом в начале отчёта. Мобильный и домашний интернет блокируют по-разному: проверяйте из той сети, которая важна (например, раздайте интернет с телефона на ноутбук).

**Linux, macOS:**

```bash
git clone https://github.com/Art-Frich/vpn-zoo-installer.git && cd vpn-zoo-installer
mkdir probe
scp root@СЕРВЕР:/etc/vpn-setup/probe-export.json probe/probe-export.json
docker build -f docker/probe.Dockerfile -t zoo-probe .
docker run --rm --cap-add NET_ADMIN --device /dev/net/tun -v "$PWD/probe:/data" zoo-probe
rm probe/probe-export.json
```

**Windows, PowerShell:**

```powershell
git clone https://github.com/Art-Frich/vpn-zoo-installer.git; cd vpn-zoo-installer
mkdir probe
scp root@СЕРВЕР:/etc/vpn-setup/probe-export.json probe\probe-export.json
docker build -f docker/probe.Dockerfile -t zoo-probe .
docker run --rm --cap-add NET_ADMIN --device /dev/net/tun -v "${PWD}\probe:/data" zoo-probe
Remove-Item probe\probe-export.json
```

Git Bash на Windows: `MSYS_NO_PATHCONV=1 docker run ... -v "$(pwd -W)/probe:/data" zoo-probe`. Нестандартный порт SSH: `scp -P ПОРТ ...`. Только часть протоколов: добавьте в конец `docker run` после `zoo-probe` аргументы `--proto vless-reality --proto hysteria2`. Клон и `docker build` нужны один раз (сборка — несколько минут, `amneziawg-go` собирается из исходников); для повторной проверки, например из другой сети, — только `scp` и `docker run`. После `git pull` пересоберите образ.

**Если вход root по SSH запрещён** (`PermitRootLogin no`): пакет лежит в каталоге root с правами 0600, сначала скопируйте его себе на сервере:

```bash
ssh -t user@СЕРВЕР 'sudo install -m 600 -o "$USER" /etc/vpn-setup/probe-export.json ~/probe-export.json'
scp user@СЕРВЕР:probe-export.json probe/probe-export.json
ssh user@СЕРВЕР rm probe-export.json
```

**Без Docker** (любой Linux с `xray`, `hysteria`, `sing-box`, `amneziawg-go`, `awg` в `PATH`): `sudo python3 zoo/zoo probe --remote probe/probe-export.json --md probe/probe-report.md --out probe/probe-report.json`. Клиента, которого нет, пробник пропустит (`SKIPPED`). Подробности, переменные путей к клиентам и параметры измерений — [docker/probe/README.md](../docker/probe/README.md).

**В пакете ключи доступа к серверу** (служебного пользователя `zoo-probe`). Передавайте только по `scp`, после проверки удалите у себя. На сервере его можно удалить командой `sudo rm /etc/vpn-setup/probe-export.json`; новый создаст команда пересборки ([выше](#самопроверка-в-конце-установки)). Если пакет утёк — отозвать ключи и выпустить новые (ключи `owner` не меняются):

```bash
cd /opt/vpn-zoo-src
sudo zoo user del zoo-probe --force          # ключи из пакета больше не работают, сам пакет удаляется
sudo bash scripts/install.sh --phase 09      # новый zoo-probe
sudo zoo probe --local --summary --export /etc/vpn-setup/probe-export.json   # новый пакет
```

### Как читать результат

Таблица в терминале и файлы `probe/probe-report.md`, `probe/probe-report.json`. В конце — сравнение «сервер ↔ у вас» по каждому протоколу:

| Вывод | Что значит | Что делать |
|---|---|---|
| **работает у вас** | Протокол проходит через вашего провайдера | Пользоваться. Держите в клиенте 2–3 рабочих протокола |
| **работает в принципе, блокируется у вас (тип)** | Сервер в порядке, режет сеть по пути | Переключиться на рабочий протокол. Тип блокировки — ниже |
| **не работает на самом сервере** | Дело не в блокировке | `sudo zoo status`, `sudo zoo probe --local --proto <id>` |
| **у вас не проверено (вердикт)** | Клиент пробника не запустился (`CLIENT_ERROR`, обычно нет `/dev/net/tun`) или его нет (`SKIPPED`) | Для AmneziaWG добавить `--cap-add NET_ADMIN --device /dev/net/tun` |
| **у вас не проверялось** | Протокол не попал в прогон (`--proto`) | Запустить без `--proto` |
| **не работает у вас (вердикт); серверной самопроверки нет** | Пакет сделан, когда самопроверки сервера ещё не было (`ZOO_SELFTEST=0` или `zoo export-probe` до первого `zoo probe --local`) | Пересобрать пакет ([выше](#самопроверка-в-конце-установки)) и проверить снова |

Вердикты отдельного протокола:

| Вердикт | Когда | Обычно значит |
|---|---|---|
| `OK` | всё прошло, ≥ 2 Мбит/с, задержка ≤ 1,5 с | работает |
| `SLOW` | медленно, или загрузка оборвалась после 64 КБ | работает плохо |
| `FREEZE_16K` | TCP: малый запрос прошёл, загрузка встала до 64 КБ | «заморозка» ТСПУ на TCP+TLS к сети хостера; помогают UDP-протоколы или другой хостер |
| `HANDSHAKE_FAIL` | порт отвечает, туннель не поднимается | блок по сигнатуре (RST на ClientHello) или устаревшие ключи |
| `IP_BLOCKED` | TCP-порт молчит; у UDP нет ответа и TCP тоже молчит | заблокирован IP (или только порт — в причине так и написано) |
| `UDP_BLOCKED` | UDP молчит, TCP того же сервера отвечает | режут UDP/QUIC; остаются TCP-протоколы |
| `SERVER_DOWN` | порт закрыт (RST, ICMP) или самопроверка сервера тоже не прошла | проблема сервера |
| `CLIENT_ERROR` | клиент пробника не запустился | проблема пробника, не сети |
| `SKIPPED` | нет клиента или в манифесте нет probe | не проверялось |

Сравнение уже есть в выводе пробника. Чтобы оно было и на сервере: вставьте `probe/probe-report.json` на странице «Проверка» админки или скопируйте отчёт и сравните в консоли:

```bash
scp probe/probe-report.json root@СЕРВЕР:      # со своей машины
sudo zoo probe --compare /var/lib/vpn-zoo/probe-local.json probe-report.json   # на сервере
```

### Нужен ли второй сервер?

**Нет.** Оба вопроса закрываются без него:
- «работает ли протокол в принципе» — клиент поднимается на самом сервере и идёт на его публичный IP (а без hairpin — через loopback);
- «блокирует ли ваш провайдер» — на этот вопрос может ответить только ваша сеть. Второй сервер за рубежом этого не скажет, а сервер в российском ДЦ скажет только про свою сеть: ТСПУ в ДЦ и у домашнего или мобильного провайдера ведут себя по-разному.

Что дала бы вторая точка (необязательно, автоматизации для неё нет): независимую проверку «снаружи». Самопроверка через собственный публичный IP может не пройти через внешний файрвол хостера (security group, анти-DDoS), так что порт, закрытый хостером снаружи, на сервере выглядит рабочим. Запуск пробника с любой машины вне РФ (тот же `docker run` или `zoo probe --remote`) отделяет «хостер не пропускает порт» от «блокирует ваш провайдер». Постоянный мониторинг из РФ — тоже только с отдельной машины; в проекте его нет.

## История проб и рейтинг

Один прогон отвечает «работает ли сейчас». Чтобы выбрать протокол под свои условия (мобильный интернет или домашний, загруженная сеть или пустая, Wi-Fi в кафе), пробы копятся и сравниваются.

**Что меряется кроме вердикта** (вердикт не меняется, всё идёт через локальный прокси протокола, ваше собственное соединение не затрагивается):

- задержка — 5 замеров на каждую из двух целей (`--latency-samples`): медиана, p90, джиттер, потери;
- скорость загрузки — 5 МБ (`--speed-mb`; на мобильном интернете `--speed-mb 1`: трафик пробы ≈ объём × число протоколов);
- отдача — по запросу, `--upload-mb 2` (POST на `speed.cloudflare.com/__up`; официального API у него нет).

**Метки условий.** `--tag mobile-mts --device pixel7` (свободный текст до 40 символов, IP-адрес в метке не принимается). Провайдер, номер ASN и страна определяются сами по вашему прямому подключению (запрос к `speed.cloudflare.com/meta`, без третьих сторон; `--no-lookup` отключает), тип сети (Wi-Fi, кабель, модем) — по интерфейсу, в Docker он не виден: различайте условия метками.

```bash
docker run --rm --cap-add NET_ADMIN --device /dev/net/tun -v "$PWD/probe:/data" \
    zoo-probe --tag mobile-mts --device pixel7 --upload-mb 2
```

**Куда копится.** На сервере — SQLite `/var/lib/vpn-zoo/probe-history.sqlite` (0600): каждый `zoo probe --local` пишется сам, клиентский отчёт — формой на странице «Проверка» (там же поля метки и устройства), командой `sudo zoo history add probe-report.json` или с вашей машины `scripts/history.sh push root@СЕРВЕР --tag mobile-mts probe/probe-report.json`. Журнал: `sudo zoo history list`. Отчёты старше 365 дней удаляются при записи нового; то, что уже выгружено в `history/` репозитория, остаётся там.

**Лучшие протоколы:**

```bash
sudo zoo probe --rank                          # по всем меткам за 30 дней
sudo zoo probe --rank --tag mobile-mts --period 7d
sudo zoo probe --rank --by isp --with-local    # по провайдерам, с прогонами самого сервера
```

Вывод (стенд Docker, один прогон `--tag ci-mobile`; на боевом сервере цифры другие):

```
== ci-mobile — прогонов: 1 (Amsterdam, Netherlands; ci-box) ==
место  протокол       оценка  успех       задержка, мс  скорость, Мбит/с
-----  -------------  ------  ----------  ------------  ----------------  -----------
1      hysteria2          99  100% (1/1)            72             206.2  мало данных
2      ss2022             94  100% (1/1)            70             185.2  мало данных
3      vless-xhttp        75  100% (1/1)            71             122.7  мало данных
—      vless-reality      74  100% (1/1)            76             128.2  мало данных
—      amneziawg          70  100% (1/1)            70             101.5  мало данных
```

Прогоны группируются по условиям (метка, без неё — провайдер); для каждого протокола считаются успех (доля OK/SLOW среди проверенных), медианная задержка и медианная скорость по удачным прогонам. Оценка: `100 × успех × (0,6 × скорость / лучшая в этих условиях + 0,4 × лучшая задержка / задержка)`. Протокол, лучший в этих условиях и по скорости, и по задержке, при полном успехе получает 100; оценки сравнимы только внутри условий. В топ-3 — только протоколы, сработавшие хотя бы раз и замеренные не меньше 3 раз. Задержка и скорость — медиана с разбросом p25–p75 (от 3 замеров). Условия, где меньше 3 прогонов, не ранжируются: «ориентир, не рейтинг», без мест и оценки. Тот же рейтинг, тренды по протоколам и журнал прогонов — на странице «Проверка» админки, блок «Лучшие протоколы».

**История в репозитории.** Каталог [history/](../history/README.md) — анонимные строки jsonl (без IP: время до часа, псевдоним сервера, провайдер, ASN, страна, метка, устройство, протокол, вердикт, числа) и сырые отчёты, зашифрованные [age](https://github.com/FiloSottile/age) на ключ истории (`history/recipients.txt`; создаёт `scripts/history.sh keygen`, приватная часть — копиями на ваши SSH-ключи в `history/key/`, новое устройство — `addkey`). Пробник пишет в него сам, если подключить каталог (`-v "$PWD/history:/history"`), или `scripts/history.sh pull root@СЕРВЕР` забирает накопленное на сервере; дальше `git add history && git commit`. Расшифровка — `scripts/history.sh decrypt ФАЙЛ.age` (нужен `age`: `winget install FiloSottile.age` или `scripts/history.sh install-age`). Что именно хранится и кто что видит — [history/README.md](../history/README.md).

## Админка и инструмент zoo

Веб-админка слушает только `127.0.0.1` и доступна через SSH-туннель.

- **Порт** — 7070; если при установке он был занят, берётся ближайший свободный выше (команду с ним показывают итог установки и `zoo web --info`). Старые установки со случайным портом переезжают на 7070 при `zoo upgrade`; порт, заданный вручную (`ZOO_WEB_PORT=N`, `ZOO_WEB_PORT_AUTO=0` в `config.env`), не меняется.
- **Помощник `zoo-admin`** (необязательно): один раз `tools/zoo-admin.sh --setup root@СЕРВЕР [-p ПОРТ] [--name ИМЯ]` (Windows: `tools/zoo-admin.ps1 -Setup`, `-Port`, `-Name`) создаёт ключ `~/.ssh/id_ed25519`, кладёт его на сервер, пишет `Host zoo` в `~/.ssh/config` и ставит команду `zoo-admin`; дальше `zoo-admin` открывает админку, `ssh zoo` — консоль. Опции — в заголовке [zoo-admin.sh](../tools/zoo-admin.sh) / [.ps1](../tools/zoo-admin.ps1).

```bash
# обычный вход: туннель и одноразовая ссылка в одной команде (туннель живёт, пока открыто окно)
ssh -t -L 7070:127.0.0.1:7070 root@СЕРВЕР zoo web --link
# вручную: туннель (ничего не печатает, окно не закрывать; после SSH_HARDEN — ssh -N -p ПОРТ_SSH …),
# затем на сервере sudo zoo web --info — команда туннеля, адрес, ссылка входа и токен
ssh -N -L 7070:127.0.0.1:7070 root@СЕРВЕР
```

Ссылка входа живёт 3 минуты: истекла — запустите команду ещё раз. Вход запоминается на 30 дней (14 дней без заходов), перезапуск админки его не сбрасывает. Неверный токен 50 раз за 5 минут закрывает вход на 5 минут; вход по ссылке при этом работает.

Один туннель сразу к админке и панели 3x-ui — готовая команда в `/root/CREDENTIALS.md`.

Страницы (пункты меню слева направо):

Трафик снимает `zoo-collector.timer` каждые 5 минут (3x-ui API, trafficStats Hysteria, `awg show`), история — в SQLite. Счётчики Xray 3x-ui обновляет примерно раз в 10 секунд: `zoo traffic --collect` сразу после подключения может ещё не увидеть трафик VLESS/XHTTP/SS-2022/TUIC. Трафик Xray берётся из счётчиков 3x-ui (`client_traffics`), а не из stats API самого Xray: панель забирает его статистику со сбросом, прямой опрос дал бы почти ноль. Админка показывает данные на момент последнего снятия (чип «на ЧЧ:ММ» у таблицы пользователей): подключившийся пару минут назад появится со следующим снятием.

## Журнал атак «Кто нас щупал»

Страница **Атаки** в админке и `zoo journal` отвечают на вопрос «чего стоит защита»: кто, с какого адреса и чем пробовал сервер снаружи. На обзоре появляется тревога, если за час попыток стало заметно больше обычного.

```bash
sudo zoo journal                      # за сутки: что делали, кто чаще всего, порты, страны
sudo zoo journal --period 7d --top 20
sudo zoo journal --all                # и «свои», и «локальные» адреса
```

| Источник | Что записывается |
|---|---|
| ufw (журнал ядра) | пакеты на закрытые порты с внешнего интерфейса (TCP SYN; UDP — на порты ниже 32768: на старших это запоздалые ответы сайтов, куда ходили пользователи) и отказы `ufw limit` на SSH. ufw пишет не чаще 3 строк в минуту на весь сервер, поэтому число попыток по портам — выборка, а не итог; адреса при этом видны |
| sshd | перебор паролей и ключей, сканеры (мусор вместо баннера, несовместимый обмен ключами); одно подключение — одно событие |
| fail2ban | баны |
| Hysteria2 | неверный ключ: строку пишет помощник `hy2-auth`, только адрес; ключ выключенного пользователя атакой не считается |
| 3x-ui, админка zoo | неудачные входы (панели слушают только loopback — это ваши опечатки) |

Чего **не видно**: чужих клиентов REALITY (Xray пишет их только на уровне Info, а на нём в журнал попадают и назначения пользователей — не включаем; косвенно: адрес, стучавшийся в закрытые порты, скорее всего щупал и 443), неверных рукопожатий AmneziaWG и пакетов с неверным паролем Salamander (их молча отбрасывают).

Что **не хранится**: трафик и назначения пользователей VPN, пароли, имена, строки журнала целиком; пакеты с VPN-интерфейсов отбрасываются. База `/var/lib/vpn-zoo/journal.sqlite` — адрес, порт, вид попытки и счётчик: по часам 8 суток, по суткам 90. Страна определяется по `geoip.dat` Xray, который уже лежит на сервере (ASN нет). Разбор идёт в `zoo-collector.service` перед снятием трафика, раз в 5 минут; при первом запуске берутся последние 3 суток журнала.

В админке таблица «Источники» ищет по базе, а не по логам: поле принимает IP или его начало (`185.220.`), страну (`cc:NL`), порт (`:22`), сервис (`ssh`, `hy2`, `f2b`, `reality`, `web`) и вид события (`ssh-auth`); условия разных видов складываются по «и». Рядом чипы сервисов и видов, выбор числа строк (15/50/100) и порядка (по числу попыток / по давности), «показать ещё» листает выдачу дальше. Клик по адресу открывает его карточку: первый и последний раз, страна, разбивка по сервисам, видам и портам, лента событий. Всё состояние — в адресе страницы, ссылкой можно поделиться. Клик по виду события (или «?» у таблицы) открывает справку из четырёх строк: что это, опасно ли, что сделала защита, что делать.

«Свой» адрес — тот, с которого был вход по ключу SSH (помнится 30 суток), или сеть из `/etc/vpn-setup/journal-ignore.txt` (адрес или CIDR в строке, `#` — комментарий). «Локальный» — не из публичного интернета (контейнеры, тесты). Оба скрыты, пока нет `--all`. Старые установки: обновите (`sudo zoo upgrade --pull --apply`), затем `cd /opt/vpn-zoo-src && sudo bash scripts/install.sh --phase 05` — для попыток по Hysteria2.

## Объём данных и чистка

Данные zoo копятся в SQLite и логах. Чистка идёт **по объёму**, а не по дням: один бюджет на всё (`ZOO_DATA_LIMIT` в `config.env`, по умолчанию 1 ГБ, но не больше 5 % диска), у каждого раздела своя доля:

| Раздел | Файл | Доля | Что режем первым |
|---|---|---|---|
| Трафик | `/var/lib/vpn-zoo/traffic.sqlite` | 20 % | самые старые записи, сначала 5-минутные, затем часовые, суточные последними |
| Журнал атак | `journal.sqlite` | 20 % | то же: часовые, затем суточные, затем список адресов |
| История проб | `probe-history.sqlite` | 20 % | сначала таблица `live` (самые старые замеры), затем самые старые отчёты |
| Логи установки | `/var/log/vpn-zoo/install-*.log` | 10 % | самые старые файлы; самый свежий остаётся |
| Дистрибутивы | `/var/lib/vpn-zoo/dist/` | 30 % | версии клиентов целиком, самые старые первыми; последнюю версию платформы бюджет не трогает (её убирает только `--clear dist`) |

Пока общий объём в бюджете, ничего не удаляется. Проверка идёт раз в 5 минут, после снятия трафика. При превышении режется раздел, сильнее всех вышедший за свою долю: самые старые записи, пока общий объём не опустится до 90 % бюджета (чтобы не чистить каждые 5 минут). Неиспользованная доля раздела не пропадает — её занимают другие. Сроки в днях (журнал атак — 90, история проб — 365, трафик — 5 мин 3 суток, час 90, сутки 1100) остаются верхней границей «старше не нужно». Сроки журнала и истории меняются только переменной окружения конкретного запуска (`ZOO_JOURNAL_KEEP_DAYS` — 7…365, `ZOO_PROBE_KEEP_DAYS` — 0 хранить всё, например `ZOO_PROBE_KEEP_DAYS=0 sudo -E zoo history add …`); в `config.env` они не действуют, а коллектор и админка берут умолчания.

Админка, «Настройки» → «Данные»: по разделу размер, полоса заполнения доли, «хранится с», «очистить» (с подтверждением; задача идёт отдельным процессом), итог «занято X из Y · свободно на диске Z», поле «Бюджет данных» (допустимо 1G, 500M, 2 ГБ; не меньше 16M; заданный в `config.env` меньше 16M не применяется — действует умолчание и горит тревога). Вне бюджета, но показаны: journald, `geo/prev` (откат geo-файлов) и `geoip.dat`. Тревоги на обзоре: свободно меньше 10 % диска; раздел чистится чаще раза в сутки (бюджет мал).

```bash
sudo zoo storage                  # сводка по разделам
sudo zoo storage --enforce        # уложить в бюджет сейчас (так же делает коллектор)
sudo zoo storage --clear traffic  # очистить раздел: traffic, journal, probe, logs, dist
sudo zoo storage --limit 2G       # бюджет (пишет ZOO_DATA_LIMIT в config.env)
```

Системный журнал journald ограничен отдельно: фаза 00 кладёт `/etc/systemd/journald.conf.d/50-vpn-zoo.conf` с `SystemMaxUse=500M` (без него — 10 % диска, до 4 ГБ). Откатить: удалить файл и `systemctl restart systemd-journald`.

## Закрыть SSH

По умолчанию инсталлер SSH не трогает: порт 22, вход по паролю и root по паролю остаются, как их настроил хостер, а перебор паролей сдерживает fail2ban (`ufw limit` не используется, D37). Закрыть SSH можно флагом `SSH_HARDEN=1` (фаза 01b): SSH переезжает на случайный высокий порт, вход только по ключу, root только по ключу (`PermitRootLogin no` остаётся `no`), `MaxAuthTries 3`, `LoginGraceTime 20`, `X11Forwarding no`. Проброс портов (`ssh -L` к админке и панели) остаётся.

Сначала нужен рабочий вход по ключу: ключ в `authorized_keys` root или пользователя с `sudo` (`ssh-copy-id root@СЕРВЕР` со своего компьютера). Без ключа фаза откажется и ничего не изменит.

**Шаг 1.** В обычной SSH-сессии:

```bash
cd /opt/vpn-zoo-src
SSH_HARDEN=1 sudo -E bash scripts/install.sh --phase 01b
```

sshd начинает слушать старый и новый порт, пароли выключаются на обоих, в ufw и fail2ban добавляется новый порт. Включается таймер отката на 10 минут, и фаза печатает точные команды.

**Шаг 2.** Не закрывая старое окно, откройте **новый** терминал, войдите на новый порт и подтвердите оттуда:

```bash
ssh -p НОВЫЙ_ПОРТ root@СЕРВЕР
cd /opt/vpn-zoo-src && SSH_CONFIRM=1 sudo -E bash scripts/install.sh --phase 01b
```

Подтверждение принимается только из сессии на новом порту, пришедшей снаружи: это и есть проверка, что вход работает и файрвол хостера порт пропускает. Сессия через VPN этого же сервера или через `ssh -J` по старому порту не подходит: она приходит с адреса самого сервера и файрвол хостера не проходит. Входите напрямую, VPN на компьютере на это время выключите. После него старый порт закрыт (sshd его не слушает, правила ufw нет), таймер снят, маршрутизация (07) и `/root/CREDENTIALS.md` обновлены, а `zoo web --info` и подсказки печатают новый порт.

**Не получилось войти?** Ничего не делайте: через 10 минут таймер вернёт порт, пароли и правила ufw как были (откат переживает перезагрузку) и запишет `SSH_HARDEN=0`. Частые причины: свой файрвол у хостера (security group, «firewall» в панели — откройте там новый порт), нет приватного ключа к ключу в `authorized_keys`, больше трёх ключей в ssh-agent (`ssh -p ПОРТ -o IdentitiesOnly=yes -i ~/.ssh/ключ …`). Пока перенос ждёт подтверждения, fail2ban не банит адрес, с которого запущен шаг 1: неудачные пробы ключей на новом порту не закроют вам SSH.

**Вернуть как было** (`SSH_HARDEN=0 sudo -E bash scripts/install.sh --phase 01b`) — тоже в два запуска, если порт менялся. Первый возвращает исходные настройки входа (пароли — как были у хостера), sshd слушает исходный порт **и** порт фазы. Второй запуск, из новой сессии на исходном порту (`ssh -p 22 …`, напрямую), закрывает порт фазы. Если на исходный порт не войти (файрвол хостера пропускает только новый), порт фазы просто остаётся открытым. Из веб-консоли хостера второй шаг — с `SSH_CONFIRM_FORCE=1`.

| Параметр | Что делает |
|---|---|
| `SSH_HARDEN=1` / `0` | закрыть SSH / вернуть исходный порт и настройки sshd (`SSH_HARDEN=0 sudo -E bash scripts/install.sh --phase 01b`, два запуска — см. выше) |
| `SSH_PORT=N\|random\|keep` | порт: свой, случайный высокий (по умолчанию) или прежний (`keep`: только запрет паролей; подтверждать из новой сессии, вошедшей по ключу) |
| `SSH_REVERT_MIN=10` | через сколько минут откатить шаг 1 без подтверждения (1–120; разовый) |
| `SSH_CONFIRM=1` | шаг 2 (разовый) |
| `SSH_CONFIRM_FORCE=1` | подтвердить без проверки сессии: из веб-консоли хостера или если SSH у вас доступен только через VPN; так же — второй `SSH_HARDEN=0` (разовый) |

С `SSH_HARDEN=1` в обычном `install.sh` шаг 1 выполняется в начале установки, а инструкция печатается ещё раз в самом конце. Отсчёт 10 минут идёт с этого момента: пока установка работает, откат откладывается. Почему два шага и что видит сканер — [DECISIONS](DECISIONS.md), [PROBE-SURFACE](PROBE-SURFACE.md) §3.1.

## Пользователи

Один пользователь зоопарка — это креды во всех включённых протоколах сразу. `owner` создаётся при установке.

```bash
sudo zoo user add ivan-petrov --note "бухгалтерия"
sudo zoo links ivan-petrov --qr          # ссылки и QR; файлы AWG — в /etc/vpn-setup/clients/ivan-petrov/
sudo zoo user disable ivan-petrov        # временно отключить; enable — вернуть
sudo zoo user rekey ivan-petrov          # новые ключи: старые перестают работать
sudo zoo user del ivan-petrov
```

- Имя: латиница в нижнем регистре, цифры, `-` и `_`, до 32 символов, первый символ — буква или цифра. Имя `zoo-probe` зарезервировано. В админке латиницу из русского имени делает сам сервер.
- В админке: «Подключить людей» (сразу списком) или «Пользователи» → «＋ Добавить пользователя». Файлы на сервере: `/etc/vpn-setup/clients/ИМЯ/amneziawg-android.conf` (Android, только выбранные приложения), `amneziawg.conf` (компьютер, iPhone; у обоих рядом `.png` с QR) и `v2rayn-routing.json` (правила v2rayN).
- Отключение в Hysteria2 и AmneziaWG рвёт сессии сразу, без рестарта сервиса.
- Xray-протоколы (VLESS, XHTTP, SS-2022, TUIC) у пользователя общие: один клиент 3x-ui на все, включается и выключается сразу во всех четырёх.
- Протокол, включённый после создания пользователей, получает их при следующем `install.sh` (или `zoo user sync`).
- Служебный `zoo-probe` скрыт из списков и отчётов по пользователям, но учтён в итогах по протоколам. Отключить его нельзя; удалить — только `zoo user del zoo-probe --force` (пакет пробника удаляется, самопроверка переходит на owner; вернуть — `install.sh --phase 09`).

У каждого свой ключ: утёкший отключается одной командой, остальных это не задевает.

## Группы и «Подключить людей»

Группа — как подключаем этих людей: протоколы, приложение на каждое устройство и список «через VPN». Человек входит в одну группу. При установке создаётся «Основная»: все включённые протоколы (она следует за включением новых) и приложения рекомендованного варианта мастера («Надёжно»: Android — AmneziaWG и Happ, iPhone — INCY, Windows — v2rayN). В неё попадают все, кто был заведён раньше. Набор «Основной» с приложением не из вариантов (прежний автоподбор ставил Hiddify) один раз заменяется этим, участники попадают в «Кому переслать». У кого протоколы заданы вручную (`zoo user add --proto`), стоит пометка «свой набор»: правка группы его протоколы не меняет. Выход в RU и DNS — на весь сервер ([параметры](#параметры)), в группу не входят.

**«Подключить людей»** — кнопка на «Обзоре» и «Группах».

- **В существующую группу** — выбрать группу (заранее не выбрана никакая) и вставить список людей. Появляется, когда хотя бы в одной группе уже есть люди.
- **Новая группа** — четыре шага на одной странице: Вариант → Приложения → Люди → Раздача.
  - **Вариант.** «Кто ставит» — по устройствам: «Телефоны — сами, компьютеры — ИТ» (по умолчанию: личные телефоны люди ставят из магазинов по сообщению, на рабочие компьютеры ставит ИТ), «Всё ставит ИТ» (и рабочие телефоны) или «Всё ставят сами»; где ставит ИТ, сервер скачает APK и установщики ([ниже](#дистрибутивы-для-групп-ставит-ит)), а сообщение человеку начинается с «VPN уже установлен». «Просто» — одно приложение на устройство: Android — AmneziaWG (список приложений уже внутри QR), iPhone — INCY с «РФ напрямую», Windows — v2rayN с правилами, Mac и Linux — v2rayN, через VPN только браузер Brave; протоколы AmneziaWG, VLESS XHTTP и запасной VLESS Vision. У «Просто» Android только на UDP — помечено оговоркой. «Надёжно» — то же и Happ на Android (VLESS по TCP), если сеть режет UDP: в сообщении Happ — отдельным блоком «Если «AmneziaWG» не подключается» после проверки, основные шаги короче. «Свой набор» — протоколы и приложения вручную. «Рекомендуем» — у варианта без оговорок, где ни одно устройство не осталось только на UDP; сейчас это «Надёжно». Протокола варианта нет на сервере — приложения подбираются под включённые. Скорость у протоколов — по замерам с устройств людей за 30 дней; пока их нет, варианты выбраны по надёжности, а ссылка «Как получить замеры →» ведёт на страницу «Проверка». Замеры даёт [пробник](#блокирует-ли-ваш-провайдер-пробник-на-вашей-машине) с компьютера в сети людей (мобильный интернет — через раздачу с телефона), отчёт вставляется на «Проверке».
  - **Приложения.** Строка на устройство: приложения и чип «все протоколы», «с оговоркой», что берёт, если не всё («VLESS (TCP)» у iPhone в «Надёжно», «UDP и TCP»), или «нет …», если не берёт ничего; в «сменить» у наборов — «нет …», чтобы их сравнить. Строка «Через VPN» называет и устройства, где список не действует (iPhone, macOS — только Brave); «сменить» — другие наборы. Устройство, отмеченное чипом после варианта (Mac), получает приложения варианта — v2rayN; AmneziaVPN — только через «сменить». Ниже — «Оговорки». Если снять все приложения, инструкции и карточки напишут «Приложения не выбраны» со ссылкой на настройку.
  - **Люди.** Название группы (своё, например «Бухгалтерия»: подставлять «Группа 3» мы перестали — потом не отличить) и список: по строке на человека — «Иван Петров», «Иван Петров; бухгалтерия» или «Иван Петров; бухгалтерия; android, windows». Разделитель — первый в строке из `;`, табуляции и запятой, поэтому «Петров, Иван» станет именем «Петров» с заметкой «Иван» — предпросмотр это подсветит, и с устройствами дальше в строке тоже. Устройства понимаются и по-русски и по маркам: айфон, андроид, samsung, xiaomi, пк (→ Windows), mac, macbook, linux — в любом поле после имени; слово, по которому не понять устройство («телефон», «смартфон», «планшет», «ноутбук», «компьютер»), и незнакомое слово в третьем поле предпросмотр покажет как «не понял: ноутбук — Windows или Mac?», а не спрячет в заметку. Устройство через пробел в конце имени («Анна Смирнова android») уходит в устройства, а не в логин; слово, которое бывает фамилией («Иван Мак»), — только вопросом. Устройство, для которого у группы нет приложения (Mac у одного человека), — в строке человека «macOS → v2rayN (галочка ниже)» и галочка «Дать группе приложение для macOS»: оно добавляется только тем, у кого это устройство указано. «Через VPN» — общий список или свой для группы — выбирается здесь же, до раздачи. Столбцы из Excel вставляются как есть, до 200 строк за раз: строка заголовка («Имя | Отдел | Телефон | Компьютер») пропускается — предпросмотр об этом пишет, «Фамилия | Имя» склеиваются в имя, устройства собираются из всех столбцов после имени, а пустая клетка устройства — подсказка «устройство не указано — будут устройства группы». Без устройств — как у группы. Логин сервер делает сам (`ivan-petrov`, повтор — `ivan-petrov-2`), в инструкциях к человеку обращаются по имени. «Проверить список →» показывает таблицу, «Создать группу и N чел.» — заводит. Тут же можно перевести в группу уже заведённых людей.
  - **Раздача.** «Карточки (печать, ZIP, CSV)», «Инструкция» (только чтение, правится на странице группы) и, если ставит ИТ, дистрибутивы.

**Страница группы** — те же настройки одной формой: сохранение применяется ко всем участникам сразу. Участники с галочками: перевести в другую группу, «Убрать из группы» (в «Основную»), «Задать отмеченным» устройства; «＋ Добавить людей списком». «Объединить с…» переводит участников в другую группу и удаляет эту. «Удалить группу…» — участников перевести в «Основную» или удалить вместе с группой; «Основная» не удаляется. Устройства одного человека — на его странице: «Профиль» → «устройства».

**Карточки для раздачи** — со страницы группы или кнопкой «Раздать» для отмеченных на «Пользователях». На человека: имя, его устройства, приложения со ссылками на магазины, QR и шаги. Главный путь — сообщение: страница человека → «Скопировать сообщение» (инструкция и его ссылки одним текстом; файл приложить отдельно) или «ZIP этого человека». Если ссылки на устройстве берут два приложения (v2rayNG и Hiddify), ключи каждого — отдельным сообщением «Ключи для «Hiddify»», в ZIP — `keys-hiddify.txt`: Hiddify из буфера берёт все ссылки текста, а VLESS он не умеет. На бумаге — только QR, остальное помечено «в сообщении»; логин и заметка на печать не идут. «Печать» — 2–3 карточки на лист A4, можно сохранить в PDF. «Скачать ZIP» — папка на человека (QR, `.conf`, `instruction.txt`) и `index.csv` для Excel (столбец «приложение» — в какое приложение ключ); «CSV: имя → ссылка» — только таблица. До 200 человек за раз. **В файлах ключи доступа: не отправляйте их через MAX и VK** — лично, на бумаге или мессенджером со сквозным шифрованием.

**Кто подключился.** Подключился — был трафик или отметка за 30 дней. На странице группы — «подключились 12 из 33» и «Ещё не подключились» (карточки только им). Пока трафик не собирался — «кто подключился — видно через 5 минут после первого сбора трафика».

### Новый сотрудник

«Подключить людей» → «В существующую группу» → список → «Добавить». После добавления — подсказка, кому раздать: одному — «сообщение» (его страница: «Скопировать сообщение», ZIP), нескольким — «Карточки для раздачи» → «Скачать ZIP», только им, не всей группе. Один человек — можно и «Пользователи» → «＋ Добавить пользователя»: там обязательно отметить его устройства.

### Потерял телефон, ушёл, «Кому переслать»

Потерял телефон — страница человека → «Не работает или медленно» → «Потерял Android» (iPhone, Windows…): новые ключи только в протоколах этого устройства, в сообщении для него — «Это настройка нового телефона: приложения и ключи — по шагам ниже». Другое его устройство с тем же ключом (у Xray ключ один на оба VLESS: Happ на телефоне и v2rayN на компьютере) названо заранее и тоже попадает в «Кому переслать» — с «удалите старые подключения» только в его приложениях; устройство с другими ключами не трогается. До встречи с человеком можно «Отключить». «Новые ключи» в шапке — ключи во всех протоколах сразу (утекли): в сообщении каждого устройства — удалить старые подключения в его приложениях (консоль: `sudo zoo user rekey ИМЯ`). Новый телефон другой (Android ↔ iPhone) — смените «устройства» в «Профиле»: «поставьте заново» перейдёт на новый. «Отключить» — временно: «Включить» вернёт доступ с теми же ключами. Ушёл — «Удалить…». После новых ключей, перевода в другую группу, смены протоколов, приложений или списка «через VPN» человек попадает в «Кому переслать»: там по его устройствам сказано, что отправить, а первая строка сообщения говорит человеку, что сделать со старым — «добавьте только новый ключ», когда группе добавили протокол (старые работают); «в «AmneziaVPN» выключите VPN и удалите подключение», когда приложение сменилось; «удалите старые подключения», когда ключи другие. Сменился только список — на его странице короткое сообщение без шагов установки: новый файл AmneziaWG или правил v2rayN (что старое удалить) или что отметить в Happ. У каждого человека — «Скопировать сообщение» (до трёх человек — прямо там) и ZIP; «Карточки (печать)» — вторая ссылка. Подсказки «не работает» называют столько получателей, сколько потом покажет «Кому переслать». Правка группы отмечает только тех, у кого на их устройствах сменились приложения или ключи: смена приложения Windows не задевает людей с одним телефоном. Где список не действует (iPhone, AmneziaVPN на Windows), его смена человека туда не добавляет. «Отправлено» снимает отметку.

Список «через VPN» группы правится на «Через VPN» (вкладка группы) или на странице группы. Он сильнее общего, а свой список человека сильнее группового.

```bash
sudo zoo group add Бухгалтерия --proto amneziawg --proto vless-xhttp --client android=amneziawg
sudo zoo user add ivan-petrov --group Бухгалтерия --note "бухгалтерия"
sudo zoo group set Бухгалтерия --proto vless-reality --proto amneziawg   # применится к участникам; в ответе — кому нужен новый QR
sudo zoo group move ivan-petrov main
sudo zoo group set Бухгалтерия --install admin   # приложения ставит ИТ: сервер начнёт скачивать APK и установщики
```

### Дистрибутивы для групп «ставит ИТ»

Где приложения ставит ИТ («Всё ставит ИТ» или компьютеры при «Телефоны — сами, компьютеры — ИТ»), сервер сам скачивает с GitHub установщики выбранных приложений для этих устройств: Android — APK, Windows — тот же файл, что у людей, которые ставят сами (v2rayN — архив «.zip» с «windows-64»), macOS — по названию из релиза, Linux — AppImage или deb. Раз в сутки и по кнопке «Обновить» у таблицы; в консоли — `sudo zoo clients --fetch-dist`. Чего нет на GitHub (App Store, Google Play, INCY), показано ссылкой на магазин; нет подходящего файла в релизе — ссылка на релиз и причина. В памятке «Как установить (для ИТ)» — и шаги, которым нужны права администратора компьютера (TUN в v2rayN на Windows), и разовая настройка приложения (в Happ — выбор приложений «через VPN», Inbounds, «РФ напрямую»; на Mac — ярлык Brave), и что делать, если Mac не открывает приложение, и последней строкой — Brave и остальные приложения списка «Через VPN» группы: людям в сообщение это не попадает, им остаётся импорт ключа и «включите». У «Ставят сами» эти шаги в сообщении с пометкой «нужны права администратора (их нет — попросите ИТ)».

Таблица — на странице группы и на шаге «Раздача»: приложение, версия, файл, размер, sha256, «Скачать». Хранятся две последние версии приложения, всего не больше 300 МБ и доли «Дистрибутивы» в [бюджете данных](#объём-данных-и-чистка). Файлы — в `/var/lib/vpn-zoo/dist/<приложение>/<версия>/`; сверить файл после скачивания: `sha256sum файл`.

## Не работает или медленно

Страница человека → «Не работает или медленно» — всегда над сообщениями (свёрнут, если тревог нет): проверка собрана из его протоколов и приложений; есть предупреждение — блок раскрыт. По порядку:

0. **Работают ли его протоколы на сервере.** Считаются только протоколы, которые берут его приложения (как в «Все ссылки и QR»), по каждому устройству. Упал сервис или порт не слушает — первая строка «На сервере не работает Hysteria2»: на каком устройстве что включить, а где другого нет — так и сказано; дело не в человеке. На «Обзоре» у такой тревоги — «Без VPN остались: Бухгалтерия (2 чел.)» — тоже по приложениям людей, а у кого основное приложение не подключится, но запасное работает, — «Офис, Android (2 чел.): пусть включат запасное «Happ»» со ссылкой «Кому написать». Упавший протокол запасным не предлагается.

1. **Доходит ли он до сервера сейчас.** Подключался в последний час — ключи верные, дело в приложении или в списке «Через VPN». Раньше — «последний раз 2 д назад: сейчас не доходит» (приложение выключено, сеть режет протокол или ключ старый). «ни разу» — ключи не добавлены или скопированы не целиком: перешлите сообщение. Отметка обновляется раз в 5 минут; у VLESS видно только «VLESS XHTTP или VLESS Vision» — счётчик у них общий. «Обзор» перечисляет тех, кто ни разу не подключался и кто пропал дольше 7 дней.
2. **UDP или TCP — по каждому его устройству.** Мобильные сети и офисный Wi-Fi часто режут UDP (Hysteria2, AmneziaWG, TUIC): «Android: только UDP» — предупреждение и что сделать (добавить группе протокол, который его приложение уже берёт, или дать приложение — названо). «Только TCP» (iPhone и Windows в готовых вариантах) — справка: обычно хватает. Правка всегда на всю группу: в строке — ссылка «Настройки группы» и сколько человек получат что переслать — тем же сравнением, что потом «Кому переслать» (добавить протокол — «ещё один ключ получат N чел., старые работают»); нужно только ему — переведите его в отдельную группу. Устройства человека не отмечены — подсказки по всем устройствам группы, и об этом строка первой.
3. **Приложение.** Связка, помеченная в каталоге «не проверено», — первая подозреваемая: дайте другое приложение (метка «ссылка не проверена» у магазина — про адрес ссылки, а не про приложение).
4. **Медленно.** AmneziaWG на iPhone, AmneziaVPN и Hiddify на компьютере пускают через VPN всё устройство: строка называет замену и какой рабочий протокол ей достанется (например, «смените Windows в группе на «v2rayN» (ему достанется VLESS XHTTP)»; достанется только UDP — тем же советом и какой TCP добавить: одна правка, одна пересылка; рабочего нет — какой протокол добавить группе). v2rayN на Windows: медленно только приложения из списка — по шагам ниже, медленно всё подряд — не активен наш набор правил (через VPN идёт весь компьютер) или дело не в VPN. Цифры speedtest (в Brave с включённым VPN и в обычном браузере — через VPN идёт только список): с VPN намного медленнее, чем без, — запасной ключ (VLESS Vision) или запасное приложение, иначе протокол, который его приложение берёт, назван; медленно у всех — «Обзор»: нагрузка процессора, «Проверка» → «Самопроверка с сервера»: сколько тянет туннель на самом сервере. Задержка на «Обзоре» — с сервера на себя, медиана малых запросов; в самопроверке — первый запрос вместе с рукопожатием, поэтому больше. Как у людей, показывает только пробник.
5. **Его сеть.** Режет ли оператор — [пробник](#блокирует-ли-ваш-провайдер-пробник-на-вашей-машине) в Docker на компьютере в той же сети; мобильный интернет — через раздачу с телефона на ноутбук. На телефоне пробник не запускается. Отказы Hysteria2 «неверный ключ» за сутки (страница «Атаки») показаны тут же: чей ключ, не видно, но если это он — у него старый ключ.
6. **Что спросить**: Wi-Fi или мобильный и какой оператор, приложение, снимок ошибки, с какого времени; если медленно — скорость на speedtest.net в Brave с включённым VPN и в обычном браузере. Потерял устройство — кнопка «Потерял Android» (и по другим его устройствам): какие ключи сменятся и какое устройство с тем же ключом настроить заново — названо до нажатия ([выше](#группы-и-подключить-людей)).

## Приложения через VPN

Через VPN идут только приложения из списка, всё остальное — российские приложения, банки, Госуслуги, MAX, новые и забытые приложения — работает напрямую и адреса сервера не видит. Факт VPN приложения на телефоне видят всё равно: его без root не скрыть.

- **Список** — `/etc/vpn-setup/allowlist.json`, пресет — весь каталог `zoo allow` (Android: Brave, Telegram из Play и с telegram.org, Telegram X, YouTube, Instagram, WhatsApp, X, Discord, Signal, ChatGPT, Claude; Windows: `brave.exe`, `Telegram.exe`, `Discord.exe`, `Signal.exe`, `ChatGPT.exe`, `claude.exe`). Зашиваем сразу всё: перевыпускать QR потом трудно, а снять лишнее пользователь может сам в клиенте. В каталоге только зарубежные сервисы, RU-приложений нет — адрес сервера через них не утекает. Неустановленные приложения Android пропускает (по коду AOSP, на телефоне не проверено).
- **Android, AmneziaWG и WG Tunnel:** список уже внутри файла и QR человека (`amneziawg-android.conf`) — ему ничего настраивать не надо. Приложения из списка лучше поставить до включения туннеля: поставленное позже попадёт в VPN после его перезапуска.
- **Android, Happ:** человек сам отмечает приложения в «Прокси для выбранных приложений».
- **Windows, v2rayN:** файл правил `v2rayn-routing.json` (v2rayN 7.25+, правило по процессам).
- **iPhone:** выбрать приложения нельзя. В INCY и Happ через VPN идёт всё, кроме российских сайтов («РФ напрямую»), в AmneziaWG — всё.
- **Компьютер в AmneziaVPN или Hiddify:** через VPN идёт весь компьютер.
- **Mac и Linux, v2rayN:** без TUN, через VPN только браузер Brave (прокси 127.0.0.1:10808), список там не действует ([USER-GUIDE](USER-GUIDE.md)).
- **Браузер для VPN — Brave** из Google Play или GitHub, не из RuStore; не браузер по умолчанию, поиск не Яндекс.

На iPhone и в полном туннеле смена списка ничего не меняет — после сохранения так и сказано, с выходом: на iPhone строже нельзя (только убрать iPhone из устройств человека), в полном туннеле — дать устройству приложение, которое берёт список. Telegram из Google Play и APK с telegram.org — разные строки: отмечен только первый — при сохранении предупреждение. В админке: «Через VPN» — общий список и вкладки групп, под таблицей — «Где список действует» по приложениям группы. Свой список человека — со ссылки на его странице. После сохранения люди попадают в «Кому переслать».

```bash
sudo zoo allow list --catalog           # список и известные приложения
sudo zoo allow add youtube              # всем: пакет YouTube (Android)
sudo zoo allow del telegram --user ivan-petrov   # свой список человека
sudo zoo links ivan-petrov --qr                 # новый QR — старый работает со старым списком
```

Инструкция для пользователей по платформам — [docs/USER-GUIDE.md](USER-GUIDE.md); её шаги по платформам собирает `zoo docs --user-guide` из каталога клиентов — те же, что админка пишет в инструкциях групп и на карточках. Механика и что режим не закрывает — [RISK-REDUCTION](RISK-REDUCTION.md) §4.

## Анти-детект и утечки IP

Главное из [docs/RISK-REDUCTION.md](RISK-REDUCTION.md):

- **Реальный риск — утечка IP сервера**, а не то, что приложение «видит VPN». Адрес утекает, когда российское приложение ходит в интернет через VPN. Главная защита — на телефоне: через VPN только выбранные приложения ([выше](#приложения-через-vpn)), клиент без открытого локального прокси (AmneziaWG, WG Tunnel; в Happ — пароль `auto`, в v2rayNG — локальный прокси выключен), «Allow LAN» и «Блокировать соединения без VPN» не включать. Механика клиентов — §4, пошагово — [USER-GUIDE](USER-GUIDE.md).
- **Что делает сервер** (§5): echo-сервисы «мой IP» (все 6 из MAX) блокируются или идут через WARP; sniffing; opt-in блок или WARP для RU-направлений (`RU_EGRESS`, `HY2_RU_EGRESS`, `AWG_RU_EGRESS`); из туннеля не видны 127.0.0.1, частные сети и сервисы сервера кроме SSH; журналы посещений выключены; BitTorrent заблокирован; уникальные параметры обфускации AmneziaWG на каждую установку; JSON-подписка 3x-ui (SOCKS без пароля у клиента) никогда не включается; панель не торчит наружу. Для AmneziaWG echo-правило не работает: там защищает только сплит на клиенте.
- **MAX, банки, Госуслуги** — §4: в режиме allowlist они идут мимо VPN без настроек; варианты от отдельного телефона и VPN на роутере до автоматизации на iPhone; что прячет факт VPN, а что только адрес.
- **Чего сервер не может**: скрыть факт VPN на телефоне, закрыть локальный прокси без пароля у клиента, спасти от бана подсети хостера (§5, «Чего сервер не может в принципе»).
- **Гигиена администратора** (§6): ничего не публиковать, не раздавать широко, ключи не пересылать через MAX/VK, бэкап `/etc/vpn-setup/` вне сервера, план на случай бана IP.

## Параметры

Задаются через окружение, сохраняются в `/etc/vpn-setup/config.env` и действуют при следующих запусках:

```bash
ENABLE_SS=1 RU_EGRESS=block sudo -E bash scripts/install.sh
```

Повторный запуск с изменённым параметром перезапускает только фазу-владельца (и маршрутизацию). `ENABLE_X=0` на установленном сервере выключает протокол: сервис или inbound остановлен, порт закрыт, манифест `enabled=false`. `ENABLE_X=1` возвращает его. То же делает кнопка «Выключить»/«Включить» на карточке протокола на «Обзоре» (задача идёт в фоне, последний включённый протокол выключить нельзя).

| Группа | Ключи | По умолчанию |
|---|---|---|
| Протоколы | `ENABLE_VLESS`, `ENABLE_XHTTP`, `ENABLE_HY2`, `ENABLE_HY2_OBFS`, `ENABLE_TUIC`, `ENABLE_AWG` | `1` |
| | `ENABLE_SS`, `ENABLE_WARP` | `0` |
| | `ENABLE_ZOO` (инструмент zoo, админка, самопроверка) | `1`; выключение после установки не реализовано |
| Движки | `AWG_ENGINE=auto\|kernel\|userspace` | `auto`: модуль ядра, если DKMS собирается, иначе `amneziawg-go` |
| | `HY2_ENGINE` | `apernet` (единственный) |
| Выход в RU | `RU_EGRESS=direct\|block\|warp` (Xray-протоколы) | `direct` |
| | `HY2_RU_EGRESS=direct\|block\|warp`, `AWG_RU_EGRESS=direct\|block` | `direct` |
| | `ENABLE_BITTORRENT=1` — пропускать BT; `ROUTING_ECHO_EXTRA=a.com,b.com` — свои echo-домены | `0`, пусто |
| Порты | `VLESS_PORT` | `443` |
| | `HY2_PORT` | `443` (UDP) |
| | `XHTTP_PORT`, `SS_PORT`, `TUIC_PORT`, `AWG_PORT`, `HY2_OBFS_PORT` | случайные высокие, выбираются один раз; никогда 1080, 3128, 8080, 9050, 2053, 54321 |
| VLESS | `VLESS_SNI` (+`VLESS_SNI_CHECK=0`), `VLESS_TARGET=host:port` | target выбирает валидатор из списка кандидатов |
| XHTTP | `XHTTP_PLACEMENT=port\|fallback`, `XHTTP_SNI`, `XHTTP_PATH`, `XHTTP_MODE` | `port` (отдельный порт) |
| Hysteria2 | `HY2_SNI`, `HY2_MASQ_URL`, `HY2_HOP=1` + `HY2_HOP_RANGE` (port hopping) | `bing.com`, `40000-49999` |
| AmneziaWG | `AWG_PROFILE=v2\|v3`, `AWG_RT=1`, `AWG_NETWORK`, `AWG_MTU`, `AWG_DNS`, `AWG_KEEPALIVE`, `AWG_NO_HWE=1` | `v2`, `10.66.66.0/24`, `1280`, Cloudflare DNS, `25` |
| Сервер | `SERVER_IP`, `LABEL` (имя в ссылках), `SSH_PORTS` | определяются сами, `vpn` |
| SSH | `SSH_HARDEN=1` — закрыть SSH (новый порт, только ключ; [выше](#закрыть-ssh)), `SSH_PORT=N\|random\|keep` | `0`, `random` |
| Панель | `PANEL_PORT`, `PANEL_PATH`, `PANEL_USER`, `PANEL_2FA=1` | случайные, 2FA выкл. |
| Данные | `ZOO_DATA_LIMIT=1G` — общий бюджет данных zoo ([ниже](#объём-данных-и-чистка)); пишется из админки или `zoo storage --limit`, install.sh его не трогает | `1G`, но не больше 5 % диска |
| Обновления ОС | `AUTO_REBOOT=0`, `AUTO_REBOOT_TIME=ЧЧ:ММ` (применяются через `--phase 00`) | автоперезагрузка в `04:00` |
| Подписка | `SUB_PUBLIC=1`, `DOMAIN` | `0`. **Заготовка:** фазы публичной подписки с доменом и TLS нет, порт подписки не открывается; ссылки выдаёт `zoo` |

Разовые переключатели, которые не сохраняются: `ZOO_SELFTEST=0` (без самопроверки), `ZOO_KEEP_LOGS`, `ZOO_KEEP_BACKUPS` (сколько журналов и бэкапов хранить, по умолчанию 10), `ZOO_VLESS_REPICK=1` вместе с `--phase 04` (выбрать REALITY target заново), `WARP_REREGISTER=1` вместе с `--phase 08` (новая регистрация WARP), `SSH_CONFIRM=1`, `SSH_CONFIRM_FORCE=1`, `SSH_REVERT_MIN` вместе с `--phase 01b` ([Закрыть SSH](#закрыть-ssh)). Полный список и владельцы ключей — [docs/ARCHITECTURE.md](ARCHITECTURE.md) §3, решения по умолчанию с обоснованием — [docs/DECISIONS.md](DECISIONS.md).

Аргументы `install.sh`:

```bash
sudo bash scripts/install.sh --dry-run       # план без изменений
sudo bash scripts/install.sh --phase 05      # одна фаза принудительно
sudo bash scripts/install.sh --only 05,07     # только эти фазы (выполненные пропускаются); --skip 06 — все, кроме
sudo bash scripts/install.sh --rerun         # пройти заново и выполненные фазы (идемпотентно)
sudo bash scripts/install.sh --force         # перезаписать чужую установку (с бэкапом)
sudo bash scripts/install.sh --reset         # очистить state (установленное не удаляется)
```

## Обновление закреплённых версий

Версии компонентов меняются в `scripts/versions.env` (версия + sha256, проверка на стенде). На сервере:

```bash
cd /opt/vpn-zoo-src && sudo git pull
sudo zoo upgrade            # план: что устарело относительно versions.env и какие фазы пройти
sudo zoo upgrade --apply    # smoke до, фазы по плану, smoke после, подсказка отката
```

`--pull` делает `git pull --ff-only` сам, `--fetch` показывает отставание от upstream, `--phase ФАЗА` добавляет фазу в план. Простой `sudo bash scripts/install.sh` после `git pull` тоже работает: копия `zoo` в `/opt/vpn-zoo` обновится (фаза 09), итог и самопроверка напечатаются снова.

Свежие версии upstream: `zoo-upstream.timer` раз в сутки спрашивает GitHub (последние 20 релизов, включая pre-release, а у кого релизов нет — теги: 3x-ui, Xray, Hysteria — репозиторий по `HY2_ENGINE`, amneziawg-tools, amneziawg-go, sing-box; таймаут 10 с, без токена) и пишет `/var/lib/vpn-zoo/upstream.json`; руками — `sudo zoo upgrade --check-upstream`. Страница «Настройки → Версии» и `zoo upgrade` только читают этот файл: колонка «Доступно» — «vX ↑» (новее закреплённого), «—» (нет новее), «не проверено»; `amneziawg-go` при движке ядра — «не используется (ядро)». Сами версии автоматически не меняются: обновление идёт через пины репозитория (`bump-pins`, sha256).

Geo-файлы маршрутизации обновляются отдельно: ежедневный таймер `vpn-zoo-geo-update.timer` с проверкой и откатом.

## Обновление с первой версии

Склонируйте v2 в постоянный каталог (первая версия советовала `/tmp`) и запустите `sudo bash scripts/install.sh` поверх старой установки. State первой версии сохраняется рядом (`state.v1`) и сбрасывается, все фазы проходят заново и переносят то, что было:

- **Hysteria2:** старый пароль становится паролем `owner`, ссылка `hysteria2://…` продолжает работать. Сервер обновится до закреплённой версии; лучше перейти на новую ссылку с `pinSHA256`.
- **VLESS:** переезжает с 8443 на 443 и получает новый REALITY target вместо `www.cbr.ru`. Inbound первой версии переносится вместе с клиентами, но ссылку VLESS нужно заменить.
- **AmneziaWG:** ключи клиента и порт сохраняются, параметры обфускации становятся уникальными. Конфиг AWG тоже нужно заменить.
- **Панель 3x-ui:** уходит с открытого порта 2053 на `127.0.0.1`, доступ через `ssh -L`.
- Появляются XHTTP, SS-2022, инструмент `zoo`, анти-утечки и самопроверка.

## Ограничения и что не проверено

- **Не проверено вживую:** боевой VPS с российским провайдером и настоящим ТСПУ (только эмулятор); модуль ядра AmneziaWG (DKMS) и цикл «HWE-ядро → reboot» — в Docker ядро чужое, проверен только `amneziawg-go`; arm64 (сервер и образ пробника на Apple Silicon); хостер без hairpin.
- **Клиентские приложения:** ссылки проверены разбором ядрами Xray и sing-box, как это делают клиенты, но не импортом в Happ, v2rayN/NG, Hiddify, NekoBox, AmneziaVPN, mihomo. Ключ `vpn://` AmneziaWG проверен по структуре. В итоге установки у AmneziaWG QR только для `.conf`; `zoo links --qr` и админка строят QR и для `vpn://`, но импорт по нему не проверялся.
- **Пробник у пользователя:** проверен на стенде и с Windows 11 (PowerShell 5.1 + Docker Desktop: `git clone`, `scp`, `docker build`, `docker run -v "${PWD}\probe:/data"`, вариант без входа root); Docker Desktop на macOS и нативный Docker на Linux-десктопе не прогонялись.
- **Не прогонялись режимы:** `XHTTP_PLACEMENT=fallback`, `AWG_PROFILE=v3`, смена `PANEL_*` после установки, `ENABLE_ZOO=0` после установки (выключения нет), `SUB_PUBLIC=1` (фазы подписки нет), кнопка обновления geo в админке.
- **Закрытие SSH (`SSH_HARDEN=1`)** проверено на стенде (22.04 с `ssh.service`, 24.04 с `ssh.socket`, в том числе откат после перезагрузки), но не на боевом VPS: файрвол хостера, облачные образы с другими drop-in в `sshd_config.d`, `Match`-блоки (фаза проверяет их через `sshd -T -C` и предупреждает, если они оставляют пароль, но не правит) и `ListenAddress` с портом (фаза отказывается) не прогонялись. Откат таймером страхует и от этого.
- **Port hopping Hysteria** пробником не проверяется: hop-порты — DNAT на внешнем интерфейсе, с сервера они недостижимы; проверяется основной порт.
- **Известные компромиссы:** TUIC-ссылка с `allow_insecure=1` без пина сертификата (в клиентах легко перехватить; пин есть только у пробника); токен пользователя Hysteria кратко виден в списке процессов; API Xray и мост TUIC на 127.0.0.1 без пароля (так устроен 3x-ui; из туннеля недоступны); geo-обновление проверяет целостность, но не пин; пакеты AWG из PPA не закреплены по версии; WARP не мониторится постоянно; исходящий порт 25 не закрыт.
- Трафик проб `zoo-probe` входит в итоги по протоколам.
- **Журнал атак:** проверен на стенде настоящими сканером, перебором SSH и неверным ключом Hysteria2; живые строки ядра «[UFW BLOCK]» стенд не отдаёт (LOG из сети контейнера не доходит до журнала), поэтому разбор ufw проверен на строках в формате ядра, вброшенных через `/dev/kmsg`; на боевом VPS и с реальными сканерами не проверялся. Чужие клиенты REALITY не видны.

## FAQ и неполадки

**Протокол «НЕ РАБОТАЕТ на самом сервере».** `sudo zoo status` (сервисы, порты, проблемы), `sudo zoo probe --local --proto <id>`, журналы: `journalctl -u x-ui`, `-u hysteria-server`, `-u awg-quick@awg0`. Повтор фазы: `sudo bash scripts/install.sh --phase <номер>`.

**VLESS «подключено», но трафика нет.** Клиент на sing-box или старое ядро Xray (см. [клиенты](#что-вы-получите)). Нужен клиент на Xray ≥26.x.

**Всё работает на сервере, у меня — нет.** Запустите [пробник](#блокирует-ли-ваш-провайдер-пробник-на-вашей-машине) из своей сети. `UDP_BLOCKED` — берите TCP-протоколы; `FREEZE_16K` — UDP-протоколы или хостер в другой сети; `HANDSHAKE_FAIL` на VLESS — SS-2022, Hysteria2 или другой SNI (`VLESS_SNI=… sudo -E bash scripts/install.sh`); `IP_BLOCKED` везде — нужен новый IP.

**Потерял ссылки.** `sudo zoo links owner --qr` или `sudo cat /root/CREDENTIALS.md`; заново напечатать итог: `sudo bash scripts/install.sh --phase 99`.

**Забыл токен админки.** `sudo zoo web --link` (одноразовая ссылка входа) или `sudo zoo web --info`; новый токен — `sudo zoo web --new-token`.

**«ни одна фаза не запускалась».** Всё уже установлено. Перезапуск выполненных фаз: `--rerun`; одной фазы: `--phase`.

**«install.sh уже запущен».** Ждите окончания другого запуска (блокировка `/run/vpn-setup.lock`).

**После reboot ядро не сменилось, фаза 02 снова просит перезагрузку.** Ядро задаёт хостер: `AWG_NO_HWE=1 sudo -E bash scripts/install.sh`.

**Фаза остановилась на «чужой установке».** На сервере уже был 3x-ui, Hysteria или AmneziaWG не от этого инсталлера. `--force` сделает бэкап в `/var/backups/vpn-setup/` и перезапишет.

**`zoo status` возвращает 1.** Есть проблема из списка: упавший сервис, закрытый порт, устаревший или ошибающийся коллектор трафика, интерфейс AWG пропал при «активном» юните.

**AmneziaWG в пробнике `CLIENT_ERROR`.** Контейнер запущен без `--cap-add NET_ADMIN --device /dev/net/tun`.

**IP сервера заблокировали.** Новый IP или VPS: склонировать репозиторий и `install.sh` на новом сервере, раздать новые ссылки. Бэкап `/etc/vpn-setup/` и `x-ui.db` держите вне сервера ([RISK-REDUCTION](RISK-REDUCTION.md) §6).
