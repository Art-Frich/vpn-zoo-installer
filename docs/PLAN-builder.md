# План: конструктор подключений и группы

Продуктовый флоу для «тупого юзера» (формулировка пользователя, 2026-10-06): от «хочу VPN
для мамы» до «мама подключена» без чтения документации. Пункт 16 в [BACKLOG.md](BACKLOG.md).

## Проблема сейчас

Всё есть, но раскидано и не связано: протоколы — на «Обзоре», клиенты — строкой «Для: Happ,
v2rayNG…» в плитке (`userviews.CLIENTS`, без версий и ссылок), учётки — на «Пользователях»,

«что выбрать», «что скачать», «что отправить человеку».

## Флоу «Новое подключение» (мастер, 4 шага)

**1. Протоколы.** Карточки протоколов с фактами для выбора, не с формулами:
- работает ли у пользователей — из клиентских проб (рейтинг, п. 11), с пометкой «мало данных»;
- работает ли с сервера сейчас — из live-замеров (п. 1);
- канал: UDP/TCP; переживает ли «белые списки» и обрывы (находка 7); батарея; скорость;
- короткая рекомендация: «мобильная сеть → Hysteria2», «домашний Wi-Fi → VLESS XHTTP»,
  «резерв → AmneziaWG».
- Выбор: основной + резервные (2–3). Предвыбор — топ по рейтингу или дефолты.
- Здесь же **название группы** («Семья», «Друзья-iPhone») — по умолчанию «Группа 1».

**2. Клиенты.** Для каждой платформы (Android, iPhone, Windows, macOS, Linux) — клиенты,
которые поддерживают *все выбранные* протоколы (или максимум из них), с:
- последней версией и ссылкой (GitHub releases / Google Play / App Store / F-Droid);
- что умеет: импорт по QR/ссылке/файлу/подписке, приложения через VPN (per-app), авто-резерв;
- предупреждения совместимости — **проверенные**, с датой и версией (пример: sing-box-клиенты
  не проходят VLESS-REALITY у Xray 26.9.30 из-за X25519MLKEM768 — Hiddify/Karing для REALITY
  не подходят);
- рекомендованный клиент на платформу отмечен.

**3. Учётки и преднастройки.**
- Создать пользователей группы (имя, заметка) или добавить существующих.
- Преднастройки группы: приложения через VPN (п. 15), российские сайты напрямую
  (RU_EGRESS), DNS.
- Индивидуальные отличия у пользователя — разрешены, видны как «свой (отличается)».

**4. Раздача.** На каждого пользователя — готовый «пакет»:
- пошаговая инструкция под его платформу и клиент: скачать (ссылка + версия) → импорт
  (QR / файл) → проверка («откройте 2ip.ru — должен быть адрес сервера, банк — свой адрес»);
- что отправить и как: текст-сообщение + QR/файл одной кнопкой «скопировать сообщение»
  / «скачать архив»; предупреждение, через какие каналы конфиг не слать (RISK-REDUCTION.md);
- рекомендации по протоколу/клиенту (MAX и компрометаторы, Brave для браузера и т.п.) —
  2–3 строки, остальное ссылкой.
- Ссылок «открыть снаружи» нет: админка только на 127.0.0.1 (D7), пакет уходит руками.

## Администрирование после

- Страница «Группы»: группа = протоколы + клиенты по платформам + преднастройки; список
  участников; трафик и здоровье группы.
- Изменение группы → пересборка файлов участников (в фоне, п. 15) → плашка «нужен новый
  QR у: …» со ссылками на пакеты.
- Перенос пользователя между группами; удаление группы — только пустой.
- Существующие пользователи при миграции → группа «Основная» с текущими настройками.

## Каталог клиентов (основа шагов 2 и 4)

- Один файл данных в репозитории (`zoo/data/clients.json`), вместо `userviews.CLIENTS`:
  клиент → платформы, протоколы (+ мин. версия, оговорки), возможности (per-app, подписки,
  импорт), ссылки по платформам, источник версии (GitHub repo или «стор, без API»),
  `verified`: дата и версия, на которой совместимость проверена.
- Источник фактов — research/2026-10-04/clients-and-allowlist_04-10-26.md + полевой тест;
  непроверенное помечать «не проверено», не выдавать за факт.
- Последние версии — тем же суточным опросом GitHub, что и п. 3 (версии сервера);
  магазинные приложения — без версии, только ссылка.
- Docker-стенд проверяет совместимость там, где клиент есть в Linux-варианте (sing-box,
  Xray, hysteria, amneziawg) — результат пишется в `verified`.

## Модель данных

- `groups.json` рядом с users: `{id, name, protocols[], clients{platform: client}, allowlist}`
  (`ru_egress` и `dns` не нужны: серверные настройки).
- Пользователь получает `group`; его `protocols` выводятся из группы (+ явные отличия).
- CLI: `zoo group add|list|set|rm`, `zoo user add <имя> --group семья`. Веб = мастер поверх CLI-
  функций (как сейчас: веб не обходит zoolib).
