# docker/probe — клиентский пробник

Каталог копируется в образ `zoo-probe` в `/opt/zoo-probe/` (`docker/probe.Dockerfile`, контекст сборки — корень репо). `scripts/` попадает туда же, в `/opt/zoo-probe/server-scripts/`, чтобы клиенты закреплялись теми же версиями из `versions.env`, что и сервер.

Что сюда кладётся:

| Файл | Назначение |
|---|---|
| `install-clients.sh` | вызывается при сборке образа, если существует. Ставит xray, hysteria, amneziawg-go (+ `awg`) по версиям и sha256 из `server-scripts/versions.env` |
| `run.py` (или аналог) | раннер: читает экспорт `zoo export-probe` (манифесты `protocols.d/*.json` с блоком `probe`), для каждого протокола поднимает клиента и меряет доступность порта, рукопожатие, малый и большой (≥512 КБ) запрос, задержку и скорость. Классификация: `OK`, `IP_BLOCKED`, `HANDSHAKE_FAIL`, `FREEZE_16K`, `UDP_BLOCKED`, `SLOW`, `SERVER_DOWN` (ARCHITECTURE.md §7) |
| `run.sh` | точка входа для `docker/test.sh`: `run.sh <контейнер-сервер> <каталог-отчёта>`. Забирает экспорт с сервера, запускает контейнер `zoo-probe` в сети `zoo-net` (напрямую), а когда появится цензор — ещё и через него. Пишет `probe-client*.json` в каталог отчёта. Ненулевой код означает провал e2e |

Тот же образ пользователь запускает на своей машине без стенда: трафик пробника идёт через его провайдера, и отчёт отвечает на вопрос «блокируется ли у меня».
