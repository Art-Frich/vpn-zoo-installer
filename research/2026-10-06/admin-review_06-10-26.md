# Ревью веб-админки zoo: план доработки

- **Дата:** 06.10.2026
- **Для кого:** сборщик (один проход), владелец
- **Контекст:** админка `zoo/zoolib/web/*` после добавления плиток «Подключение» с окнами. Владелец просит: меньше текста, ровные сетки, live, быстрые вкладки, вход без поиска токена.

## 0. Как собрано

Рой из 5 ревьюеров, у каждого своя линза: скорость, визуальный дизайн, безопасность, удобство, лаконичность. Каждый читал код и смотрел живой стенд (127.0.0.1:24305 через `ssh -L`, только GET и вход). Скорость дополнительно профилировали локально (cProfile через `app.handle` и `ZooEnv` из тестов, синтетика за 90 дней при 600 IP/сутки, это темп живого стенда). Новый UI плиток рендерили локально с подставными ссылками.

На стенде стоит **старая сборка**: там ещё нет плиток и окон, `app.js?v=0db62d6615` против локального `7622acb5df`. Всё, что касается окон «Подключение», проверено 📄 по коду и локальному рендеру.

Ведущий свёл 76 находок в один план: убрал дубли, развёл противоречия (ниже — «Решения ведущего»), находки P2 перенёс в бэклог.

## 1. Итог по линзам

| Линза | Главное |
|---|---|
| Скорость | Сам код дешёвый: /users, /apps, /probe, /traffic считаются за 0–30 мс. Время уходит на транспорт и повторную работу. (1) Сервер отвечает по HTTP/1.0, поэтому каждый запрос открывает новый канал SSH: +1 RTT, ≈55 мс. (2) Нет gzip: страница больше 14 КБ после простоя требует лишний RTT, ≈70 мс. (3) Страница пользователя весит 206 КБ, из них 93% — встроенные QR. (4) Live каждые 10 с пересчитывает /traffic и /journal, хотя данные меняются раз в 5 мин. Кэш статуса живёт 5 с, а live опрашивает раз в 10 с, поэтому промах на каждом обновлении. `scope_of` в журнале занимает 75% времени рендера. |
| Дизайн | Новые плитки визуально сломаны двумя багами CSS. `.s1–.s8` из графиков красят фон плиток, и на цветном фоне не прочитать подписи. `.variant{display:grid}` перебивает `hidden`, поэтому все варианты в окне видны разом и вкладки не работают. Дальше: на телефоне навигация и широкие таблицы уходят за край, KPI-плитки не выровнены, пустые состояния оформлены четырьмя разными способами, серые абзацы-пояснения на каждой странице. |
| Безопасность | Серьёзных уязвимостей нет: CSP, Host, CSRF + Origin, SameSite=Strict, экранирование и раздача файлов в порядке. Главная проблема — удобство входа. Сессии живут только в памяти, у cookie нет Max-Age, cookie общие для всех портов 127.0.0.1. Live тратит flash-сообщения и вечно продлевает сессию. Мелочи: кэши ссылок не чистятся, страница 500 показывает сырой stderr, URL панели виден, хотя PANEL_PATH помечен «скрыто». |
| Удобство | Трение на обоих концах основного пути. Вход: после рестарта и раз в сутки снова ищи токен. Выдача подключения: блок внизу страницы, не понятно, с чего начать, нет «скопировать всё». По пути: из тревог некуда перейти, разрушительные кнопки срабатывают без подтверждения, цифры трафика противоречат друг другу (самопроверка), «Журнал» по умолчанию показывает ASCII-QR секретных ссылок, страница задачи пробника подсвечивает «Настройки». |
| Лаконичность | Видимых слов: Обзор 201, Пользователи 97, Приложения 219, Трафик 177, Проверка 343, Атаки 434, Настройки 217 плюс ≈95 строк config.env, страница пользователя 462. Около 60% прозы объясняет, как всё устроено внутри, и ни к какому действию не ведёт. Правило: видна одна строка, остальное — в `title=` или в свёрнутое «?». Это сокращает текст на 55–65%, и ни одно действие не теряется. |

### Решения ведущего (противоречия между линзами)

1. **Где хранить сессии.** U1 предлагал подписанную cookie без состояния, SEC-01 — файл. Выбран **файл** `web-sessions.json` (0600, в нём только `sha256(sid)` и отпечаток токена). Так выход из сессии и «выйти везде» работают по-настоящему, а `--new-token` отзывает сессии автоматически.
2. **Ссылка для входа.** U1 предлагал `#t=TOKEN` во фрагменте, SEC-02 — одноразовую HMAC-ссылку. Выбрана **HMAC-ссылка** `?once=n.e.s`. Токен не попадает ни в историю браузера, ни в терминал, ссылка живёт 3 минуты, GET её не расходует.
3. **Лёгкая страница пользователя.** PERF-1 предлагал QR отдельным `<img>`, SEC-12 — фрагмент окна целиком через fetch. Выбран **`<img data-src>`**: проще, CSP не трогаем, без JS-шаблонов. Подгрузку фрагмента окна (SEC-12) переносим в бэклог.
4. **Скачивание файла.** PERF-7 и SEC-08 объединены: файл адресуется **по имени**, bash-модули не вызываются вообще.
5. **Мобильная вёрстка.** Админка открывается через `ssh -L`, обычно с ПК. Поэтому в P1 только дешёвое (навигация, складывание таблиц), двойные графики (V5) — в бэклог.
6. **«Журнал» и «Атаки».** Пункт «Журнал» (системные логи) переименовываем в **«Логи»**, «Атаки» не трогаем.

**P0-4. Транспорт: keep-alive и gzip** (PERF-2, PERF-3)
- Файлы: `web/server.py`, `web/assets.py`.
- `Handler.protocol_version="HTTP/1.1"`, `timeout=15`.
- `Connection: close` на ответах 400/413 из-за кривого Content-Length.
- В `_send` сжимать, если выполнены все условия:
  - в `Accept-Encoding` есть `gzip`;
  - тип `text/*`, `*javascript`, `image/svg+xml`;
  - тело больше 1000 байт.
- Сжатие: `gzip.compress(body, 5)` + заголовки `Content-Encoding: gzip` и `Vary: Accept-Encoding`.
- CSS и JS сжать один раз при импорте (`CSS_GZ` / `JS_GZ`).
- Готово, когда:
  - тест поднимает сервер на сокете и делает два GET через одно `http.client.HTTPConnection`, оба 200;
  - с `Accept-Encoding: gzip` ответ распаковывается и совпадает с ответом без сжатия;
  - редирект 303 с пустым телом не зависает.

**P0-5. Вход без поиска токена: часть 1** (SEC-01, SEC-03/C14, SEC-06, U1)
- Файлы: `web/auth.py`, `web/app.py`, `web/__init__.py` (`cmd_web --new-token` удаляет файл), `zoolib/paths.py` при необходимости.
- Хранилище: `Auth(token, store=paths.state_dir()/'web-sessions.json')`, запись через `fsutil.atomic_write_json(mode=0o600)`.
- Схема `{"fp": sha256(token)[:16], "s": {sha256(sid): {csrf, created, last}}}`.
- Если `fp` не совпал с текущим токеном, сессии сбрасываются. Flash не сохраняются.
- TTL: простой 14 дней, абсолютный 30 дней. Cookie с `max_age=ABSOLUTE_TTL`.
- `session(sid, touch=…)`: live-запрос (`X-Zoo-Live: 1`) время простоя не продлевает. `last` пишется на диск не чаще раза в 10 мин.
- Форма входа:
  - скрытое `username` (`autocomplete=username`, значение `zoo <LABEL|SERVER_IP>`), чтобы менеджер паролей сохранил токен;
  - метка «Токен», подсказка «Токен: `sudo zoo web --link`», блокировка — «Подождите N с».
- Готово, когда тесты проверяют:
  - вход, затем новый `Auth` с тем же файлом — сессия жива;
  - с другим токеном — `None`;
  - файл создаётся с правами 0600 (на POSIX), в файле нет `sid` в открытом виде;
  - live-запрос не сдвигает `last`.
- Строка «Неверный токен» остаётся (`test_web.py:292`).

### P1 — желательно

**P1-1. Вход: одноразовая ссылка и cookie по порту** (SEC-02, SEC-04 п.1, SEC-14, SEC-10)
- Файлы: `web/app.py`, `web/auth.py`, `web/__init__.py` (`zoo web --link`, `--info` печатает ссылку), `web/assets.py`.
- CLI печатает `http://127.0.0.1:PORT/login?once=n.e.s`, где `s=HMAC(token, n.e)[:32]`, `e=now+180`.
- GET /login показывает форму с hidden `once` и `lc`; `form[data-autosubmit]` отправляет её сам.
- POST проверяет `compare_digest`, `e`, однократность `n` (множество в памяти до `e`). Вход по ссылке обходит блокировку.
- Блокировка: порог 50 за 5 мин.
- Имена cookie `zoo_sid_<port>` / `zoo_login_<port>`.
- GET /login повторно использует корректный `zoo_login`.
- Подсказка в README: одна строка `ssh -t -L P:127.0.0.1:P user@IP sudo zoo web --link`.
- Готово, когда тесты проверяют: повторное использование, просрочку, подделку подписи; GET ссылку не расходует; две вкладки входа не ломают друг друга.

**P1-2. Live: не тратить flash, 304, без потери обработчиков, понятное истечение сессии** (SEC-05, PERF-4, PERF-13, SEC-11, U15)
- Файлы: `web/app.py`, `web/views.py`, `web/journalviews.py`, `web/assets.py`.
- При `X-Zoo-Live` flash не вынимаются. Переключатель периода тоже шлёт этот заголовок.
- `ETag` = sha1 тела без «обновлено HH:MM:SS». JS шлёт `If-None-Match`, на 304 разметку не трогает.
- /traffic и /journal кэшируются по `(path, query, ts последнего сбора)` на 600 с.
- JS:
  - делегированные `focusin`/`change` для `data-select`/`data-fill`;
  - пауза live при `dialog[open]`;
  - проверять `a.origin` и `content-type`.
- Если live-запрос редиректит на /login: в подвале ссылка «сессия истекла — войти» с `next`. Ошибка 401 даёт кнопку «Войти».
- Готово, когда тесты проверяют:
  - flash, затем live-GET, затем обычный GET — flash на месте;
  - второй live-GET с ETag получает 304 и пустое тело;
  - JS содержит `dialog[open]` и делегирование.

**P1-3. Серверная скорость** (PERF-5, PERF-6, PERF-7+SEC-08, PERF-8, PERF-9, PERF-11+SEC-07)
- Файлы: `zoolib/journal.py`, `web/views.py`, `zoolib/status.py`, `zoolib/system.py`, `web/userviews.py`, `zoolib/users.py`, `web/app.py`.
- `journal.py`: `lru_cache` на `_is_global(ip)`; `scope_of` сначала проверяет `own`. `journal.alerts` — через `app.cached('journal-alerts', 60)`.
- `status.collect` разделить:
  - метрики `/proc` — на каждый запрос;
  - медленная часть — `app.cached('status-slow', 60)`, `invalidate('status')` чистит оба ключа;
  - `cert_info` кэшировать по `(path, mtime)`.
- `/logs` и `/settings` берут юниты из манифестов + `system.unit_states`, без `status.collect`.
- Скачивание файла по имени:
  - маршрут `/users/{name}/file/(?P<fname>[A-Za-z0-9._-]{1,64})`, `_file_ok(clients_dir/name/fname)`, без вызова модулей;
  - заголовок `filename*=UTF-8''…`.
- `users.user_links`: модули параллельно через `ThreadPoolExecutor`, порядок сохраняется. Сначала синхронно вызвать один Xray-модуль: `xui_hdr` создаёт файл заголовка без блокировки (`scripts/lib/xui.sh:102`).
- Кэш ссылок `links:{name}` → `(stamp, data)`:
  - TTL 3600;
  - при записи просроченные удалять;
  - `user_delete`/`user_toggle`/`apps_post` инвалидируют ключ и `qr._svg_cache`;
  - `qr._svg_cache` — LRU на 64.
- Готово, когда:
  - локальный профиль `/journal?period=90d` на синтетике 600 IP/сутки быстрее как минимум в 1,8 раза;
  - тест: `user_file` по имени работает без вызова `protolib` (мок, который падает при вызове);
  - тест: `user_links` возвращает тот же порядок.

**P1-4. Обзор, Трафик, Настройки: тише и короче** (C5, C6, V10 частично, U5, C7, C4, V12, U10, U3, C10)
