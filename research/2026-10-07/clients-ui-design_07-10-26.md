# Выбор приложений: «устройство → одна строка» (07.10.2026)

Это решение по жалобе владельца: «Happ лежит в “Других клиентах”, но он же есть в наборе Android — почему в двух местах? Каша, сложно выглядит». Рой предложил три дизайна, здесь итог судьи. Код не менялся.

## 1. Проблема

На шаге 2 мастера (`groupviews._clients_block`) у каждой платформы свой fieldset. В нём три вещи: карточки предложенных приложений, список «Другие клиенты (N)» и карточки с россыпью чипов. Подбор (`groups.suggest_clients`) идёт по каждой платформе отдельно, жадно, и ставит «нет в РФ-магазине» **выше покрытия**.

Фактический вывод `default_clients` для группы Hysteria2 + XHTTP + AmneziaWG на текущем каталоге:

| Устройство | Сейчас | Что не так |
|---|---|---|
| Android | Happ + AmneziaWG | — |
| iPhone | sing-box + INCY + AmneziaVPN | 3 приложения; Happ (`no_ru_store: ios`) уехал в «Другие клиенты» |
| Windows | v2rayN + AmneziaVPN | — |

Итого: Happ в одном месте «рекомендуем», в другом «другие», на iPhone три приложения, всего 6 разных. Страница /clients повторяет ту же схему: карточки по платформам плюс матрица, где каждое приложение встречается снова.

Корень проблемы: единица экрана — **список приложений платформы**. Любое кросс-платформенное приложение неизбежно появляется в нескольких списках с разным статусом.

## 2. Оценки (1–10)

| Критерий | A. Устройство → одна строка | B. Карточка на приложение | C. Матрица приложение × устройство |
|---|---|---|---|
| Понятность для владельца | **9** — «на телефон ставим X» | 6 — сетка + карточки + «Не хватает» | 7 — таблица с галочками, «·»-ячейки неочевидны |
| Приложений на человека | **9** — жёстко ≤ 2 на устройство | 8 — общий подбор, лимит мягкий | 8 — то же |
| Нет дублей / путаницы | 8 — «Итого» один раз, альтернативы только в «сменить» | 7 — сетка всё равно повторяет имена | **9** — строка = приложение |
| Компактность | **9** — 3 строки + итог | 5 — три блока | 7 — 3–4 строки, «заменить» под каждой |
| Работает без Hiddify | **9** — только статусы каталога | 8 | 8 |
| Цена реализации | **8** — хранение и «Подключить» не трогаем, только `_clients_block` и сортировка | 5 — общий подбор, штрафы, новая сетка, JS | 5 — swap, распад строк, preset в Group |
| **Сумма** | **52** | 39 | 44 |

**Победитель — A.** Он отвечает на вопрос, который реально задаёт человек: «что поставить на мой телефон». Он же самый короткий и дешёвый.

Что взято у других:
- **из C:** строка «Итого» перечисляет приложения **с устройствами** («Happ — Android, iPhone»): так видно, что это одно приложение, а не два. Свёрнутый вид шага в одну строку, когда всё покрыто. На /clients одна строка на приложение со столбцами устройств вместо карточек по платформам.
- **из B и C:** межустройственный тай-брейк: при прочих равных брать приложение, уже выбранное на другом устройстве. Но он стоит **после** «рекомендовано каталогом», чтобы на Android не вытеснить AmneziaWG в пользу AmneziaVPN (баг Doze #3255).
- **из B:** «/clients и мастер считают “что ставить” одной функцией», чтобы справка и мастер не противоречили друг другу.

## 3. Итоговый дизайн

### 3.1 Шаг 2 мастера «Приложения»

Группа Hysteria2 + XHTTP + AmneziaWG, текущий каталог:

```
 1 Протоколы ── 2 Приложения ── 3 Люди ── 4 Раздача
┌────────────────────────────────────────────────────────────────────┐
│ Устройства  [✓ Android] [✓ iPhone] [✓ Windows] [ macOS ] [ Linux ] │
│                                                                    │
│ Android   Happ + AmneziaWG                  все 3     сменить ▸    │
│ iPhone    Happ + AmneziaVPN                 все 3     сменить ▸    │
│           ! Happ нет в App Store РФ                                │
│ Windows   v2rayN + AmneziaVPN               все 3     сменить ▸    │
│                                                                    │
│ Итого 4: Happ — Android, iPhone · AmneziaVPN — iPhone, Windows ·   │
│          AmneziaWG — Android · v2rayN — Windows                    │
│                                              [Назад]  [Далее]      │
└────────────────────────────────────────────────────────────────────┘
```

«сменить» у iPhone раскрыт (`<details>`, радиокнопки `set:ios`, порядок задаёт ключ из §4, первая — по умолчанию):

```
│ iPhone    Happ + AmneziaVPN                 все 3     сменить ▾    │
│   (•) Happ + AmneziaVPN       все 3           Happ нет в App Store РФ
│   ( ) INCY + AmneziaVPN       без Hysteria2   оба в App Store РФ   │
│   ( ) sing-box + AmneziaVPN   без XHTTP                            │
│   ( ) Не нужен iPhone                                              │
│                                                  [Обновить]        │
```

Правила:
- **Чипы устройств** заменяют «Другие платформы» и неявное «ничего не отмечено = не нужна». По умолчанию включены Android, iPhone и Windows.
- **Одна строка на устройство:** набор, метка «все N» (зелёная) или «без X» (жёлтая), «сменить». Подвох (нет в РФ-магазине) — максимум одна строка под ней. Версий, ссылок, чипов протоколов и «подробнее» на этом шаге нет: они есть на шаге «Раздача» и на /clients.
- **Наборы, а не галочки:** в «сменить» показано не больше 4 наборов из 1–2 приложений (лучшие по ключу) и «Не нужен <устройство>». Если двумя приложениями всё не покрыть, строка честно говорит «без X», третье приложение не добавляется.
- **Нет «Других клиентов».** Приложение видно в строке устройства (там оно выбрано) или внутри «сменить» этого же устройства (как альтернатива). Глобальных списков нет.
- **Плашка «Одно приложение на …: Hiddify»** появляется над строками, если у всех включённых устройств выбран один и тот же набор из одного приложения.
- **Свёрнутый вид (из C):** при повторном открытии шага, если всё покрыто и подвохов нет, показывается одна строка: `Приложения: Happ — Android, iPhone · v2rayN — Windows  [изменить]`.
- Сноска «на устройстве не проверено» — одна, мелким шрифтом под «Итого», и только если в наборах есть непроверенное приложение.

Группа только Hysteria2, текущий каталог и после подтверждения Hiddify:

```
сейчас:                                    Hiddify hysteria2: ok
Android  Happ           готово             ┌ Одно приложение на Android и Windows: Hiddify ┐
iPhone   sing-box       готово             Android  Hiddify     готово
Windows  v2rayN         готово             iPhone   sing-box    готово
Итого 3                                    Windows  Hiddify     готово
                                           Итого 2: Hiddify — Android, Windows · sing-box — iPhone
```

Пограничные случаи: `Linux  hysteria (консоль)  готово`; `macOS  нет приложения под эти протоколы` (сменить не показывается).

### 3.3 «Подключить» (у человека и группы)

Логика не меняется: блок уже берёт `g.clients[plat]` через `clientviews.group_prefs`. Что нужно для согласованности:
- порядок приложений внутри платформы остаётся по PRIORITY (как сейчас `suggest_clients`), иначе изменится текст инструкции и `pack_sig` покажет ложное «нужен новый текст»;
- в заголовке блока то же имя набора, что в строке мастера («Happ + AmneziaWG»). Для человека без группы («все включённые») набор считает та же `suggest_set`, что и «Ставить» на /clients;
- если в строке устройства «без X», раздел для протокола X в сообщении человеку **не появляется** (сейчас `_plan` и так пропускает непокрытое — проверить тестом).

## 4. Изменения в данных и логике

Хранение **не меняется**: `Group.clients {platform: [ids]}`, устройство включено, если ключ есть и список не пуст. Схема `clients.json` тоже не меняется.

**`zoo/zoolib/groups.py`**
- Новая `client_sets(cat, plat, protocols, max_apps=2, prefer=frozenset()) -> list[dict]`: все наборы из 1–2 приложений из `client_options`, покрывающие хотя бы один протокол. Поля: `ids`, `covers`, `missing`, `foreign`, `rec`. Сортировка по ключу:
  `(len(missing), foreign, len(ids), -rec, -len(set(ids) & prefer), порядок client_options)`.
  Наборы, строго доминируемые другим (то же покрытие при большем числе приложений), отбрасываются. `ids` внутри набора упорядочены по PRIORITY первого покрытого протокола, как сейчас. Объём перебора — до ~70 пар на платформу.
- `suggest_clients(cat, plat, protocols, prefer=...)` = `client_sets(...)[0]["ids"]`. Сигнатура совместима, поэтому `default_clients`, CLI `--client` и `group_prefs` не ломаются.
- Новая `suggest_set(cat, plats, protocols) -> {plat: ids}`: обходит устройства по порядку (android, ios, windows, …), передавая уже выбранные `ids` в `prefer`. Её зовут `default_clients`, `normalize_clients` и /clients.
- `coverage()` не меняется.
- **Главное отличие от нынешнего подбора:** покрытие выше РФ-магазина и лимит 2. Отсюда iPhone = Happ + AmneziaVPN вместо трёх приложений.

**`zoo/zoolib/web/groupviews.py`**
- `Draft`: поле `devices: list[str]` (форма `dev=<plat>`), по умолчанию `MAIN_PLATFORMS`; для существующей группы — ключи `g.clients`. `from_form`: `clients[plat] = form["set:"+plat].split("+")` для включённых `dev`; `none` равно выключенному устройству. Старое поле `client:<plat>` читается как запасной путь (одна версия, потом удалить).
- `clients_for` учитывает и устройства: `"protocols|devices"`. При смене любого из них набор пересчитывается.
- `normalize_clients`: вместо `suggest_clients` по платформам — `suggest_set` по `d.devices`. Платформы вне `devices` отбрасываются.
- `_clients_block` переписывается: чипы, строки устройств, `<details>` «сменить» с радиокнопками, плашка «одно приложение», «Итого». Короткую метку «все N / без X» дает `coverage`.
- Удаляются: `_client_option`, `set_summary` (метку заменяет `_set_label`), «Другие клиенты», «Другие платформы».

**`zoo/zoolib/web/clientviews.py`**
- `clients_page`: чипы `?dev=`, блок «Ставить» = `suggest_set(...)[dev]` под включённые протоколы, одна таблица «Все приложения» (строка = приложение, столбцы = Android/iPhone/Windows/ещё, протоколы чипами, версия, ссылки в `<details>`). Карточки по платформам и матрица `matrix` удаляются.
- `MAIN_PLATFORMS` остаётся (дефолт чипов).

**`zoo/zoolib/web/assets.py`** (JS из файла, CSP та же): при смене радиокнопки или чипа обновлять текст строки и «Итого» (заменяет нынешний обработчик `data_sum`/`data_sumtext`). Без JS всё работает по кнопкам «Обновить» / «Далее».

**`zoo/data/clients.json`** — только данные после стенда: статусы Hiddify `hysteria2` / `hysteria2-obfs` / `tuic` (и `platforms.ios`, если есть в App Store и проходит). Подтвердить Hysteria2 у Happ на iOS (сейчас «ok по документации») тем же прогоном: от этого зависит дефолт iPhone.

**Пресеты (BACKLOG п. 17)** ложатся сверху без второго интерфейса: пресет задаёт протоколы и устройства, а шаг 2 показывает те же строки в свёрнутом виде. «Свой набор» — тот же шаг, раскрытый. Поле `preset` в Group — уже в рамках п. 17, не здесь.

## 5. Миграция

- Данные групп не мигрируют. Группа с 3 приложениями на платформу показывается строкой `свой набор: A + B + C` (жёлтая метка «больше 2»), а первой радиокнопкой в «сменить» идёт именно он. Без смены протоколов или устройств подбор её не трогает.
- Группа, у которой платформы нет в `clients`, открывается с выключенным чипом этого устройства.
- `pack_sig` у старых групп не меняется, потому что не меняется `g.clients` → ложных «нужен новый текст» нет. Проверить тестом.
- Одна версия формы принимает и `client:<plat>`, и `set:<plat>`.

## 7. Что убирается явно

- «Другие клиенты (N)» у каждой платформы.
- «Другие платформы» (заменены чипами устройств) и правило «ничего не отмечено = платформа не нужна».
- Галочки отдельных приложений (`client:<plat>`) на шаге 2 — заменены наборами-радиокнопками.
- На шаге 2: чипы протоколов, «приложения: …», версия, ссылки скачивания, «подробнее», бейдж «рекомендуем» у карточек.
- Строка «Набор: … — покрывает 2 из 3: для … нет клиента» — сжата до «все 3» / «без X».
- На /clients: карточки по платформам и отдельная матрица «Что умеют клиенты» — слиты в одну таблицу «Все приложения».
- Третье приложение на устройство по умолчанию (доступно через CLI `--client` и у старых групп).

## 8. Открытые решения владельца

1. **Дефолт iPhone.** Happ + AmneziaVPN (всё покрыто, нужен иностранный Apple ID) или INCY + AmneziaVPN (в App Store РФ, но без Hysteria2). В дизайне первое, потому что «сначала покрытие», и Happ при этом совпадает с Android. Решить после проверки Happ на iOS.
2. **Лимит 2** — по умолчанию, без настройки в UI. Поднять можно константой `max_apps`.
