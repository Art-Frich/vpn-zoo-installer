# «Подключить людей» (Get started): сводный дизайн-ревью, 07.10.2026

Источник: четыре ревью от 07.10.2026. Двое смотрели живую админку (127.0.0.1:24305, только GET и переходы между шагами /connect/new) и локальный ZooEnv, включая создание групп на 2 и 33 человека в обоих режимах. Один делал скриншоты в headless Chrome на 1280 и 380 px. Четвёртый сверял каталог по App Store, Play и MS Store. Код не менялся.

Охват: Обзор → /connect/new (вариант → протоколы → приложения → люди) → /connect/done, а также страницы, на которые ведёт мастер: /groups/<id>, /handoff, /clients, /users/<name>.

Принцип исправлений: у каждой настройки одно место правки, одно название и один формат. Все остальные экраны показывают её только для чтения, с ссылкой «изменить →» в каноническое место.

## Решения, принятые здесь (спорное между ревью)

| Вопрос | Решение |
|---|---|
| Слово «Приложения» | «Приложения» означает только VPN-приложения на устройстве. Пункт меню /clients «Клиенты» → «Приложения». Пункт меню /apps «Приложения» → «Через VPN». Список Telegram/YouTube везде называется «Через VPN» |
| Название текста | «Инструкция» везде: на done, на странице группы, у человека, в /handoff, в instruction.txt |
| Подстановка имени | В редакторе показывается «{имя}», а `{name}` хранится внутри и тоже принимается. Где человек известен, сразу подставляется его имя |
| Правка инструкции | Только на /groups/<id>#text. На done и /users только чтение, «Скопировать» и «Изменить для группы →». Несохраняемой правки нет |
| Кто ставит | Один контрол, переключатель «Ставят сами / Ставит ИТ», стоит первым в блоке «Приложения» (мастер и группа). Отправляется формой, черновик не теряет |
| Шаги мастера | «Вариант → Приложения → Люди → Раздача». «Протоколы» — подшаг, только после «Свой набор» или по ссылке «сменить протоколы» |
| Название группы | Одно поле вверху шага «Люди», по умолчанию «Группа N». Подпись «Название группы», на странице группы такая же |
| Вход | Кнопка на Обзоре, H1 мастера и кнопка на /groups называются «Подключить людей» |
| Скорость | См. раздел «Скорость»: живые Мбит/с не показываем нигде |
| iPhone в режиме «сами» | Приложение должно быть в российском App Store, если такое есть (INCY, AmneziaWG). «Одно приложение на всех» — только запасной критерий при равенстве |
| sing-box | Факт в каталоге исправляем (он есть в App Store). В подбор не берём, пока не выдаём JSON-профили |

## Скорость: единая подача (P0-9, P1-16)

Сейчас у скорости три источника: live (1 МБ раз в час, задержка до gstatic), самопроверка /probe (5 МБ) и клиентские пробы. Живые цифры: Hysteria2 9.6 / 408 / 65 Мбит/с, XHTTP 51 / 141 / 44. Live по UDP занижен в 20–50 раз, и возраст у задержки и скорости разный.

Решение:
1. **В мастере и на /groups/<id>** у протокола одна метка (`Fact.chip`):
   - если клиентских проб ≥ 3 за 30 дней: `у людей ≈65 Мбит/с · 76 мс` (медианы; дата и N — в title);
   - иначе, если live ok: `работает · 63 мс`;
   - если live сбой: `chip bad` «не отвечает».
   Чипов «с сервера: …», «у клиентов: 2 из 2 · мало данных», джиттера и отдельного чипа UDP/TCP нет. UDP/TCP входят во фразу назначения.
2. **Назначение протокола** — одна строка вместо «ориентир — …»: Hysteria2 «Быстрый, основной (UDP)»; Hysteria2 + Salamander «Если Hysteria2 режут»; VLESS XHTTP «Если режут UDP»; VLESS Vision «Если режут UDP, запасной»; AmneziaWG «Запасной»; TUIC «Запасной (UDP)».
3. **Пресет**: под ним одна строка «почему», из того же источника, по которому сделан выбор: «быстрее всего у людей: ≈65 Мбит/с» или «замеров с устройств пока нет — выбран по надёжности».
4. **Ёмкость сервера** (самопроверка, 5 МБ) показывается только на /probe и на плитках Обзора, с подписью «сервер тянет ≈408 Мбит/с · 06.10». Live-Мбит/с не показывается нигде.
5. **P2**: в probe/live.py либо убрать замер скорости, либо считать 5 МБ раз в сутки (SPEED_BYTES). Если live-скорость где-то останется, возраст пишется у числа.
