## Находки (что исправить)

1. **[репо] Загрузки с GitHub без докачки** — при медленном CDN установка рискует упасть по таймауту. Нужно: докачка (`curl -C -`), таймаут по скорости вместо общего, понятное сообщение и ручной путь «положить архив в /var/cache/vpn-zoo/».
2. **[репо] Пробник через локальный TUN-VPN**: проверка «TCP-порт доступен» даёт 1 мс — соединение принимает TUN клиента (sing-box) на самом ПК, а не сервер. Вердикты IP_BLOCKED/доступность порта в таком режиме недостоверны; пробник должен это распознавать и предупреждать.
3. **[репо] Пробник: «выход не с IP сервера»** для VLESS — ложная тревога: Xray выходит с IPv6 сервера (`2a01:…`), а сравнение идёт только с IPv4. Учитывать все адреса сервера.
4. **[разобрать] SS-2022 FREEZE_16K через немецкий VPN** — это не ТСПУ (путь вне РФ). Гипотезы: MTU двойного туннеля, связка SS-2022 + TUN Hiddify. Проверить без VPN и с другим MTU.
5. **[разобрать] VLESS-XHTTP заметно медленнее** (19 и 25 Мбит/с против 50–100 у Reality) — и на сервере, и у клиента. Проверить режим (packet-up/stream-up), XMUX.
6. **[ожидаемо] `ufw limit` на SSH** придерживал самого владельца при частых подключениях подряд (6 за 30 с) — это работа защиты; для серий команд использовать одно SSH-подключение (ControlMaster).

## Исправлено и проверено на этом же VPS (06.10, коммит 2da9f8c)

- **Находка 1:** `download_verified` — постоянный `.part` + `curl -C -`, обрыв по скорости (<10 КБ/с дольше минуты) вместо 600 с. Проверка: загрузка архива 3x-ui оборвана на 79,9 МБ, повторный запуск дотянул остаток, sha256 совпал. (В этот момент GitHub с VPS уже отдавал быстро — утренняя медлительность была временной.)
- **Находка 2:** пробник стучится на закрытый порт сервера перед прогоном; через Hiddify TUN соединение принимается мгновенно → в отчёте предупреждение «TCP перехватывает локальный VPN/TUN… блокировки провайдера этот прогон не показывает». Подтверждено вживую.
- **Находка 3:** пакет пробника несёт все адреса сервера (`server_ips`: IPv4 и IPv6); выход Xray с IPv6 сервера больше не помечается как «не с IP сервера». Подтверждено вживую.
- Осталось: в режиме перехвата вердикт FREEZE_16K подписан «типичная заморозка ТСПУ» — неверно для пути через VPN (поправить текст); находки 4 (SS-2022) и 5 (XHTTP) — разобрать.

## Через провайдера владельца (06.10, маршрут /32 мимо Hiddify, сервер видит RU-адрес провайдера)

Пробник `home-isp`: Hysteria2 OK (66 мс, 65 Мбит/с), AmneziaWG OK (170 мс, 73), VLESS-Reality OK (71), VLESS-XHTTP OK (77 мс, 63), SS-2022 FREEZE_16K. Провайдер не блокирует ни один из четырёх основных протоколов.

**Находка 7 — выборочная потеря первых пакетов данных TCP-туннелей.** tcpdump на сервере во время прогона:
- SS-2022: TCP-рукопожатие проходит, **ни одного пакета данных** до сервера не доходит, сервер рвёт по таймауту; первые 1–2 соединения иногда проходят, дальше — почти все мертвы; на самом сервере (hairpin) SS работает (162 Мбит/с).
- VLESS-Reality: из 7 соединений полного цикла 3 «мёртвых» (0 байт в обе стороны после рукопожатия), остальные нормальные, включая загрузку 5 МБ. Отсюда и «задержка —» в отчёте: падают именно соединения замера задержки.
- **Обычный HTTPS на тот же порт 443** (REALITY отдаёт сайт-прикрытие) — 10 последовательных и 6 параллельных без единой потери.
- UDP (Hysteria2, AmneziaWG) не затронуты.
- Одинаково через провайдера и через немецкий VPN.

Гипотезы: (а) DPI, отличающий клиентов туннелей от браузера (на пути, общем для обоих маршрутов, — ближе к серверу/хостеру); (б) крупное первое сообщение клиента (ClientHello uTLS Chrome с X25519MLKEM768 ≈ 1,8 КБ; SS-2022 со случайным padding) разбивается на 2 сегмента и плохо переживает какой-то узел; ~~(в) сетевой стек Docker Desktop/WSL2~~ — **опровергнуто**: Xray 26.9.30 для Windows прямо на ПК (без Docker), тот же маршрут через провайдера, 10 запросов подряд: **VLESS-Reality 5/10 — первые пять проходят, все следующие умирают; SS-2022 0/10**. Похоже на счётчик новых соединений клиента туннеля к IP:порту (браузерный HTTPS он не трогает).

Практический вывод: устойчивее протоколы с малым числом долгих соединений — UDP (Hysteria2, Salamander, TUIC, AmneziaWG) и XHTTP (мультиплексирует запросы); сильнее страдают VLESS+Vision и SS-2022 (каждый запрос — новое TCP-соединение). Следующий шаг (не сделан): тот же тест на сервере другого хостера — чтобы отделить «хостер» от «пути».
